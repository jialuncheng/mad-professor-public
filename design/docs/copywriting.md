# 文案規範 · MadPro UI

> 所有介面文字（按鈕、tooltip、modal、訊息、錯誤）必須遵循本規範。

---

## 1. 語氣（Tone）

**命令式（imperative，動詞開頭）**

| ✅ | ❌ |
|---|---|
| 上傳文件 | 文件上傳 |
| 刪除文件 | 文件刪除 |
| 切換語言 | 語言切換按鈕 |
| 收合本欄 | 本欄收合 |
| 移動到資料夾 | 資料夾移動 |
| 確定刪除？ | 你確定要刪除嗎？ |

**例外**：對話 / 系統訊息（如 AI 回應、error message）允許描述式。

---

## 2. 標點規範

### 2.1 句末
**不加句號**。所有 UI 文字（按鈕、tooltip、提示、modal 內描述）。

| ✅ | ❌ |
|---|---|
| 輸入問題（Ctrl+Enter 送出） | 輸入問題（Ctrl+Enter 送出）。 |
| 選擇文件後開始提問 | 選擇文件後開始提問。 |
| 系統將根據類型選擇最佳解析方式 | 系統將根據類型選擇最佳解析方式。 |

例外：散文式段落（如 AI 回應內容、文章內文）保留標點完整。

### 2.2 半形 vs 全形
- **純英文／純數字**：半形標點、半形括號 `( )`、半形冒號 `:`
- **純中文**：全形標點、全形括號 `（）`、全形冒號 `：`
- **中英混排**：依**句子整體語境**選一致；混排中**主體為中文**時用全形

```
✅ 「上傳成功（共 3 筆）」
✅ 「Files uploaded: 3 items」
❌ 「上傳成功 (共 3 筆)」（半形括號夾中文）
❌ 「Files uploaded：3 items」（全形冒號夾英文）
```

### 2.3 中英 / 中數字之間的空格
中文與英文、中文與阿拉伯數字之間**加半形空格**：

| ✅ | ❌ |
|---|---|
| Ctrl+Enter 送出 | Ctrl+Enter送出 |
| 上限 100 MB | 上限100MB |
| AI 問答 | AI問答 |
| Phase 3.4 上線 | Phase3.4上線 |

例外：英文／數字緊鄰**全形標點**時不加空格。
- ✅ 「上限 100 MB，請壓縮後重試」
- ❌ 「上限 100 MB ，請壓縮後重試」

### 2.4 引號
- 引用句子用「」
- 引用程式 / 代號用半形 `` ` ` ``（純英文 ID、檔名）
- 不使用 ""（中文不用直引號）

## 3. 按鈕標籤

### 3.1 長度
- **Modal primary button**：≤ 6 字
- 一般按鈕：≤ 4 字理想，最多 6 字
- icon-only tooltip：2–6 字

### 3.2 危險動作
**疑問句式**，避免肯定命令。

| ✅ | ❌ |
|---|---|
| 確定刪除？ | 刪除 |
| 確定清空對話？ | 清空 |
| 確定登出？ | 登出（純按鈕） |

例外：tooltip 中的「退出系統」「清除殘檔」屬**功能標籤**而非確認操作，不必加問號。確認對話框（confirm dialog）內才用問號式。

## 4. Tooltip 文案

### 4.1 格式
- 2–6 字
- 動詞開頭（命令式）或單純名詞（功能標籤）
- 無句末標點
- 不重複按鈕已顯露的文字（icon-only 沒文字，所以 tooltip 是唯一說明）

### 4.2 對照表（目前所有 icon）

| Icon | data-tip | 註 |
|---|---|---|
| 漢堡（左 / 右） | 收合本欄 | 收合時切為「展開本欄」 |
| 新資料夾 | 新資料夾 | |
| ⋯（per-item） | 文件選單 | |
| ⋯（folder）| 資料夾選單 | |
| 登出 | 退出系統 | |
| 清理 | 清除殘檔 | |
| 幫助 | 系統介紹 | |
| 上傳 | 上傳文件 | |
| 切換風格 | 切換風格 | prototype only；後端未實作 |
| 切換中／英 | 切換語言 | （目前文字含括號狀態，視需要可改純短句）|
| 列印 | 列印文件 | |
| 搜尋 toggle | Search 開關 | 保留 Search 英文 |
| 匯出 MD | 下載 MD | |

## 5. 錯誤訊息結構

**三段式**：發生什麼，為什麼，怎麼辦。以全形逗號連接、無句末標點。

```
上傳失敗，檔案超過 100 MB，請壓縮後重試
處理失敗，連線中斷，請重新整理頁面
搜尋無結果，當前資料夾沒有符合條件的文件，請改用「全部」過濾
```

### 5.1 簡化版（短）
單一原因不必三段：
```
✅ 名稱需 1–50 字元
✅ 僅支援 PDF 格式
```

### 5.2 規範
- **永遠提供「下一步可操作」**
- 若用戶無能為力，至少告訴他「可重試 / 聯絡支援」
- 不要使用「未知錯誤」當完整訊息；至少給 status code

---

## 6. 提示訊息（非錯誤）

### 6.1 系統流程訊息
```
✅ 內容已可閱讀，AI 問答準備中
✅ 上傳中
✅ 翻譯中 42%
```

### 6.2 空狀態
```
✅ 從左側選擇文件
✅ 選擇文件後開始提問
✅ 針對文件提問
```

## 7. 術語表（強制使用）

| 概念 | 統一用詞 | 不可用 |
|---|---|---|
| 上傳的論文／PDF | **文件** | 論文、文章、檔案、paper |
| 使用者與 AI 的訊息往來 | **對話** | 問答、聊天、chat（除非屬功能名稱如「AI 問答」）|
| 後端進度階段名 | 直接用後端 `stage_name` | 不自行翻譯 |
| 資料夾 | **資料夾** | 目錄、folder（除技術文件）|
| 「處理中」進度文字 | 依後端 `stage_name`：上傳中／翻譯中／建立索引中 | 通用「處理中」 |

例外：
- 「AI 問答」是右欄的**標題**（功能名），固定使用
- 「Search 開關」中保留 Search 英文，屬命名選擇

---

## 8. 中英混雜接受度

| 場景 | 可混 | 範例 |
|---|---|---|
| 功能名稱 | ✅ | AI 問答、Search 開關、Ctrl+Enter |
| 技術代號 | ✅ | UUID、Markdown、SSE |
| 動詞 | ❌ | upload → 上傳；delete → 刪除 |
| 一般名詞 | ❌ | file → 文件；message → 訊息 |

---

## 9. 大小寫

- 英文縮寫全大寫：`AI`、`MD`、`PDF`、`API`、`UI`
- 多字英文按品牌大小寫：`Markdown`、`Helvetica`、`Ctrl+Enter`
- 中文不分大小寫，按該名詞慣例

---

## 10. 反例

- ❌ 「上傳失敗。」（句末加句號）
- ❌ 「上限100MB」（中數字之間無空格）
- ❌ 「請選擇doc type」（中英間半形且 type 屬一般名詞應翻譯）
- ❌ 「論文上傳」「文章刪除」（動詞放後 + 用論文／文章而非文件）
- ❌ 「未知錯誤」（無下一步）
- ❌ 「(共 3 筆)」中混半形括號
