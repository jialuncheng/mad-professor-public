## A. domain 生成

| # | 項 | 位置 |
|---|---|---|
| 1 | 生成器 | `processor/domain_detector.py:22` `class DomainDetector` |
| 2 | prompt | 內嵌字串 `DOMAIN_PROMPT`（line 9–18，非外部 .txt 檔）|
| 3 | 模型 | `settings.LLM_DOMAIN_MODEL` 經 `LLMClient.chat_with_image`（line 50–56），讀第一頁文字（前 4000 字）＋第一頁 2× 倍率 JPEG 截圖 |
| 4 | 觸發 stage | `pipeline_core.py:60, 74` stage `"detect_domain"` → `_stage_detect_domain`（line 534–540），呼叫 `domain_detector.detect(str(pdf_path))`；任一失敗 soft return `""` |
| 5 | 並行 | `analyze` + `detect_domain` 以 ThreadPoolExecutor max_workers=2 並行（pipeline_core.py:277–319），早期就跑、與 analyze 同時完成 |
| 6 | 結果寫入 | `output_paths['_domain'] = result or ''`（pipeline_core.py:307），失敗時 `output_paths['_domain'] = ''`（line 318）|

prompt 重點（domain_detector.py 內嵌，**不在 `prompt/` 目錄下**）：
- 「請判斷此文件的『具體主題領域』，回傳一個 10–30 字的短句，要具體、不要泛泛分類」
- 範例：「體育新聞 - 環義自由車賽報導」、「植物分子生物學 - 多重營養逆境調控」、「電力電子技術 - 高壓直流系統架構」
- 失敗回 `""`，**永不 raise**

→ domain 是 **「分類冒號子主題」的中文短句**，10–30 字，由 Vision LLM 看第一頁產出。

### B-3 兩個 processor 對 domain 的使用方式

#### translate_processor.py（同 file:223–235）
- 既有 per-doc_type `style_hints` dict（D-1 報告已列）

  domain = getattr(self, 'domain', '')
  if domain:
      system_prompt = system_prompt + f"\n\n本文件主題領域：{domain}，請以該領域標準術語翻譯。"

### B-4 未使用的 stage
- `doc_analyzer.py`（heading_fix / structure）：**未取 domain**（doc_type 已足夠路由）
- `pdf_processor` / `md_processor` / `md_restore_processor` / `tiling_processor` / `rag_processor` / `image_caption_processor` / `slides_processor`：grep 0 命中——domain 不參與這些 stage

### B-5 結論
**pipeline 內 domain 注入是已驗證範式**：translate / extra_info 兩處皆以
「附加一行 `本文件主題領域：{domain}` 字串」方式對 prompt 增量注入，
domain 為空時不影響任何輸出（`if domain:` 守門）。

## C. 寫入 DB

### C-1 schema 位置
`models.py:104`：
```python
domain: Mapped[Optional[str]] = mapped_column(Text, nullable=True)
```
**獨立欄位**（不是塞在 `metadata_json` 裡）。

→ baron 背景說「DB Paper 表已有 metadata_json 欄位（含 domain 等）」**不完全準確**：
- domain 是**獨立 Text 欄位** `Paper.domain`（schema v1，原本就有）
- metadata_json 是 Phase 4.5 加的，存 Stage A/B 的 title/authors/abstract 等
- 兩者**並存獨立**，不互含

### C-2 寫入路徑
| 點 | 行為 |
|---|---|
| pipeline_core 最末 upsert | `paper_manager.upsert_paper(..., domain=output_paths.get('_domain'), ...)`（pipeline_core.py:461） |
| paper_manager.upsert_paper | `domain_val = (domain or '').strip() or None`（line 238）；create 寫 `domain=domain_val`（line 251）；update 走「空值不覆蓋」`if domain_val: p.domain = domain_val`（line 263–264） |

### C-3 空值與 fallback
- detect_domain stage failure soft → `output_paths['_domain'] = ''`
- upsert 收到空字串 → 轉 None，nullable 欄位存 NULL
- 既有空值不覆蓋策略：一次失敗的 detect_domain 不會清掉先前正確的 domain
- AI 端取值要處理 `None` / 空字串（fallback 用通用名詞「文件」）

## D. AI 對話端能否取得 domain

### D-1 paper_manager 端：未注入 paper_data
- `preload_vector_stores`（line 383–399）：遍歷 `Paper` 已 `done` 列，
  呼叫 `ai_core.add_paper_vector_store(uuid, vstore)` 與
  `ai_core.load_paper_cache(uuid, str(rtree))`——**只傳 paper_uuid + 檔路徑**，
  不傳 domain。
- `load_paper_resources`（line 402–414）：同上，亦不傳 domain。

### D-2 ai_core.load_paper_cache：載入內容
- ai_core.py:93–106：`paper_data = json.load(open(rag_tree_path))`
- 即 `paper_data = rag_tree.json 內容`
- **rag_tree.json 不含 domain**（grep `processor/rag_processor.py domain` → 0 命中；
  rag_tree 是章節樹 + summary，與 domain 無關）

### D-3 AI_professor_chat.set_paper_context 收到的結構
從 `AI_professor_chat.py` 對 `paper_data` 的使用看欄位（grep `paper_data.get`）：
- `translated_title` / `title`（line 130, 178, 219）
- `summary`（line 181）
- `sections`（line 183）

→ paper_data ≈ `{'title', 'translated_title', 'summary', 'sections', ...}`。
**無 domain 欄位**。

### D-4 結論
**AI 對話端完全拿不到 domain**：
- DB 有（Paper.domain）
- pipeline 已用（translate / extra_info）
- 但 AI cache 路徑完全沒被注入

### D-5 最小注入點
| 選項 | 工程量 | 評估 |
|---|---|---|
| **(a) paper_manager preload/load_paper_resources 注入 paper_data** | 最小 | 兩函式皆已遍歷 `Paper` row，加 1 行從 `p.domain` 寫入 cache。但 `ai_core.load_paper_cache` 目前簽名只收 `(paper_id, rag_tree_path)`，需擴成可接 domain（kwarg）或事後 mutate `_paper_cache[paper_id]['_domain']` |
| (b) `_to_dict` 加 `domain` + web_server chat endpoint 查並傳 | 中 | 需動 chat endpoint 簽名鏈 |
| (c) AI_professor_chat 載入 character prompt 時臨時查 DB | 中 | 每次 chat 多 1 SELECT；架構不一致（其他 cache 都 preload） |

→ **(a) 最小且符合既有 cache 預載架構**。`load_paper_cache` 內把
`paper_data['_domain'] = ...` 設好即可，AI_professor_chat 之後從
`current_paper_data.get('_domain', '')` 取用。

## E. 各 prompt 對 domain 的使用方式建議

### E-1 ai_character_prompt.txt（**最大效益**）
**目前**：通篇「論文」「學術導師」「文獻」（4 個學術化命中）。
**建議注入位置**：開頭 persona 段落，加 1 行「當前文件主題：{domain}」即可。
範例（不執行）：
```
你是一位專業的文件閱讀助手...
當前文件主題：{domain}
請以該領域的專業知識協助使用者理解文件內容...
```
domain 空時：caller 端 `domain or "（主題未標註）"` 或乾脆跳過該行
（建議用條件性注入：domain 非空才加，避免 prompt 出現「主題：」空欄）。
若再搭配前一輪 router 已修的「文件」用詞，AI 會自動轉用 domain 中的
名詞（如「履歷」「報導」「簡報」）——baron 預期效果即此。

### E-2 ai_explain_prompt.txt
- 目前 1 行：「你是一位專業的學術導師，當前協助學習者理解的論文或書籍為：{title}」
- 建議：「當前協助學習者理解的{文件}為：{title}（主題：{domain}）」；
  domain 非空時加括號片段、空時省略。

### E-3 summary_generation_prompt.txt
- 雖屬章節精煉 pipeline-internal prompt，但**已經有 domain 注入（extra_info_processor
  在 user_prompt 前置 `本文件主題領域：{domain}`）**。
- system prompt（即 summary_generation_prompt.txt 本體）目前**不需**再注入
  domain——caller 端已透過 user_prompt 前置注入。改 system prompt 反而
  重複。
- 若要改，**改其「論文」措辭**（前份盤點 C-1 列為必改）足矣；domain 注入
  由 extra_info_processor 既有機制負責。

### E-4 router prompt
- 上輪已修為通用「文件」用詞；router 的職責是**分類查詢策略**
  （rag/macro/direct/page），不需要知道文件主題就能判斷。
- **不建議**注入 domain。會擾亂 router 對「閒聊 vs 文件相關」的判斷。

### E-5 translate 與其他
- `content_translate_prompt.txt` / `title_translate_prompt.txt`：**caller
  已在 system prompt 末尾附加** `本文件主題領域：{domain}` 整行（translate_processor.py:235）。
  prompt 本體**不需動**。
- `formula_analysis_prompt.txt` / `question_generation_prompt.txt` /
  `graph_question_generation_prompt.txt`：caller 既有 domain 前置（extra_info_processor
  user_prompt 前綴）已涵蓋；本體 prompt 不必再加。

## F. 實際 DB 看到的 domain 內容（評估描述性）

### F-1 本環境無法查 DB

- 故無法以本機 SQL 直接驗證。下方依 baron 提供的樣本與 prompt 設計目標
  做語意評估。

### F-2 樣本評估（baron 提供）
| Paper | domain（baron 給樣本） | 評估 |
|---|---|---|
| 800-vdc | 「半導體電源轉換器 - 800V 直流配電架構」 | ✓ 具體、可直入 prompt（「該領域的專業知識」） |
| Giro news | 「體育新聞 - 2026 環義自由車賽第九站賽事前瞻」 | ✓ 自帶「新聞」名詞，AI 會自然用「報導」「賽段」等詞 |
| ALi slides | 「半導體企業戰略 - 傳統 IC 設計轉型智慧家庭 AI 網關」 | ✓ 自帶「戰略」「網關」業務語彙，AI 易用「策略框架」等簡報用詞 |
| DeHunt 履歷 | （baron 標記待驗證）若同 ALi 樣本則語意偏離 | **疑點**：履歷與 ALi 簡報 domain 一模一樣不合理——可能是 detect_domain 的第一頁判斷失準（履歷封面字面與 IC 業務文件相近），或是樣本被 baron 暫填同字串待查 |

### F-3 描述性整體評估
- prompt（`DOMAIN_PROMPT`）已強制「具體、不泛泛分類」「10–30 字短句」「冒號分類-子主題格式」，輸出結構化、可直接內嵌 prompt
- 樣本顯示**多數情境輸出合用**；履歷類因首頁特性（公司名/職稱列表 vs 履歷本體）可能誤判
- **不需再加工**——直接內嵌 `"當前文件主題：{domain}"` 即可；
  domain 空字串守門（`if domain:`）保證不打擾 AI

### F-4 風險點（需 baron 注意，但不在本輪修法範圍）
- 履歷的 domain 若真誤判（DeHunt 案例），會把履歷講成「IC 設計轉型」
  脈絡——AI 注入後可能更精準誤導
- 中長期可考慮：detect_domain prompt 加入「履歷類文件首頁特徵識別」
  或允許使用者上傳時手動填 domain（如 doc_type 一樣）

## G. 推薦下一步（**不執行**）

### G-1 最小工程方案（**強烈推薦**）

#### 步驟（皆未實作）
1. **paper_manager.preload_vector_stores + load_paper_resources** 各加
   ~2 行：載入完 paper_data 後注入 `_domain`
   ```
   ai_core.load_paper_cache(paper_uuid, str(rtree))   # 既有
   # ↓ 新增
   pd = ai_core._paper_cache.get(paper_uuid)
   if pd is not None and p.domain:
       pd['_domain'] = p.domain
   ```
   （或：`load_paper_cache` 簽名擴 `domain=None` kwarg，內部 `paper_data['_domain']=domain`，更內聚但動 ai_core 1 行）
2. **AI_professor_chat 載入 character prompt 時** 從
   `self.current_paper_data.get('_domain', '')` 取，`if domain:` 條件性
   附加「當前文件主題：{domain}」一行到 system prompt。
3. **同 ai_explain_prompt** 同模式（單一變數 `{title}` 後加 `{domain}` 條件）
   或 caller 端條件式串接。

#### 影響檔
- `paper_manager.py`：preload_vector_stores / load_paper_resources 各 +2–3 行（或 +1 行若改 load_paper_cache 簽名）
- `ai_core.py`：load_paper_cache 視做法 0 行或 +1 kwarg + 1 行
- `AI_professor_chat.py`：character prompt 載入後字串組裝 +3–5 行（單一條件附加）
- prompt 檔本體：**不必修改 character_prompt 變數**（caller 端純串接 `本文件主題：{domain}` 字串，沿用 translate/extra_info 既有範式）
  - 若要改 prompt 本體加 `{domain}` 變數也可，但 `.format()` 需處理空值；
    **推薦 caller 端條件串接**，與 translate_processor.py:233–235 完全同模式

#### 工程量
- **小（30–60 分）**
- 與 D-1（router/character/explain/summary 措辭改文件）**正交**，可並行
- prompt 為純文字檔即時讀，**不需重啟**；.py 改動需重啟 web_server
