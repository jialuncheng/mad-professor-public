# 2026-05-20 Phase 4.7a：DB 加 original_filename 欄位

4 檔（models / paper_manager / web_server / pipeline_core）。未動 4.7c
前端、未動 pipeline 主流程（僅 process() 加 passthrough kwarg）、未動
metadata 抽取、未動 pdf_processor / ai_core / rag_retriever。

## 關鍵設計決策（誠實標註：未採推薦選項 B，理由如下）

查證 web_server：**DB Paper row 只在 pipeline 完成時由
`upsert_paper` 建立**（`upsert_paper` 內 `status='done'` 為**無條件**
寫死）；上傳階段只寫記憶體 `processing_tasks`，**無任何「先 upsert 一次」
時機點**。且 `_to_dict`/`list_papers` 對前端**無 status 過濾**——側欄列表
直接來自 list_papers。

→ 若採**選項 B**（上傳時先 upsert 寫 original_filename）：會在論文尚未
處理時就建出一筆 `status='done'` 的 row，導致：
- 側欄（GET /api/papers）立即出現一筆無內容的論文（現況是處理完才出現）
- `preload_vector_stores`（撈 status='done'）可能撈到未完成論文
這等同改動論文生命週期語義，違反「不動 pipeline 流程」之精神，屬回歸。

**故改採選項 A/C（零回歸 thread-through）**：web_server 上傳時把原始檔名
存進**既有** `processing_tasks` dict（已存 `_pdf_path`/`_owner_id`），
經 `confirm_type → run_pipeline → pipeline.process()` 一路 passthrough
到**既有那一次** `upsert_paper`。pipeline_core 只加一個 optional kwarg
傳遞，**不新增 stage、不改控制流、不改既有那次 upsert 的時機**——非
「主流程」變更。spec D 標題本就要求「pipeline_core 把 original_filename
傳給 upsert」，此實作完全符合該目標，僅「怎麼拿到」選 A/C 而非 B。

## 改動

### A. models.Paper（+欄位）
`original_filename: Mapped[Optional[str]] = mapped_column(String(255),
nullable=True)`（接在 metadata_json 後）。`String` 既有 import。
nullable → 4.7a 前舊資料無此欄不爆。

### B/C. paper_manager.upsert_paper（+參數 + 空值不覆蓋）
簽名末加 `original_filename: Optional[str] = None`；
`orig_fn_val = (original_filename or '').strip() or None`；
create 寫入、update `if orig_fn_val:`（與 domain/doc_type 同策略：空值
不覆蓋既有，避免二次寫入清掉首寫值）。docstring 同步。

### E. paper_manager._to_dict（+欄位）
回傳加 `'original_filename': p.original_filename`（舊資料 None）。前端
可取得但 4.7c 才顯示。

### D. thread-through（web_server + pipeline_core）
- web_server upload：processing_tasks 加 `'_original_filename': file.filename`
  （未 sanitize，原樣）。
- web_server confirm_type：從 task 取 `_original_filename` →
  `background_tasks.add_task(run_pipeline, …, original_filename)`。
- web_server run_pipeline：簽名加 `original_filename: Optional[str]=None`
  → 傳入 `pipeline.process(... original_filename=original_filename)`。
- pipeline_core.process：簽名加 `original_filename: Optional[str]=None`
  → 傳給既有那次 `upsert_paper(... original_filename=original_filename)`。

## F. DB schema 變動

無 Alembic。舊 row（將來保留時）因 nullable 不爆，`_to_dict` 回 None。

## 風險
- pipeline_core.process 多一 optional kwarg：唯一呼叫端 web_server
  run_pipeline 已同步；其他既有呼叫（測試/未帶此參）走預設 None，行為
  不變。
- web_server run_pipeline 多一 optional 參數且 confirm_type 已對應傳入；
  background_tasks 以位置參數帶入，順序正確（已 py_compile + 審查）。
- 無 schema 遷移、無前端、無 pipeline 流程/階段變更，回歸面極小。
