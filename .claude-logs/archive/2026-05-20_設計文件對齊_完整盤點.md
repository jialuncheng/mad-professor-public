## 任務 B：三題具體實作方案

### B-1 #2 textarea 不自動回彈

**真因**：
- `static/index.html:1659–1663` prototype `ta` listener 監聽 `input` 事件做
  自動長高（max 240）。
- `static/index.html:2144` sendMessage 程式設值 `input.value = ''`。
- 程式設值**不會觸發** `input` 事件 → `ta` listener 不執行 → height 卡在
  原本擴張的尺寸。
- Phase 4.7c §3.3 刪除業務 `autosizeChatInput` 後沒有補上「送出後縮回」
  的觸發。

**設計 spec 期望**（components §6.2）：「自動長高：min 32 / max 240 /
**隨內容增長**」。隱含「內容歸零時也應縮回 min 32」。

**最小修法**（1 行，在 sendMessage 內）：
```js
// before
input.value = '';
// after — 程式設值補觸發 input 事件，讓 prototype ta listener 重算高度
input.value = '';
input.dispatchEvent(new Event('input'));
```
或更直接（不依賴 prototype handler 存在）：
```js
input.value = '';
input.style.height = '';   // 讓 CSS min-height 接管
```
**推薦 A（dispatchEvent）**：保留 prototype handler 為單一真源、未來
prototype 改 listener 邏輯時自動跟著走。

工程量：**小（5 分）**；風險：低。

### B-2 #3 空的上傳仍會彈 doc_type modal

**真因**：
- `static/index.html:1493` prototype demo handler：
  ```js
  document.getElementById('upload-btn').addEventListener('click', () => openModal('confirm-modal'));
  ```
- 此 handler **早於業務** addEventListener 註冊（prototype JS 在前、業務在
  後），點 upload-btn 時**先**跑 demo openModal、**再**跑業務（file picker）。
- Phase 4.7c §3.2 已記此 limitation：業務 stopImmediatePropagation 無法
  取消「已執行」的 prototype handler。

**設計 spec 期望**（interaction §9 上傳鏈）：
```
點 #upload-btn → 原生 file picker → POST upload → 顯示 #confirm-modal
```
**唯一路徑**——demo handler 違反 spec（spec 沒說「點 upload-btn 立即開
modal」）。

**最小修法**（刪 1 行 prototype JS）：
```diff
-  document.getElementById('upload-btn').addEventListener('click', () => openModal('confirm-modal'));
```
**確認不破壞 prototype**：
- prototype 該 handler 是「demo 用，方便沒接後端時預覽 confirm-modal」
- 業務 upload-btn handler（`static/index.html:2224`）已接管完整流程
- 移除後 `#upload-btn` 唯一 handler = 業務 = 與 spec 一致
- 同類前輪「破例改 prototype JS」案例（theme path 兩處 4.7c §5 + 後續
  補正）已建立先例

工程量：**極小（< 5 分）**；風險：低。
