### 3.1 `#web-search-toggle` — 以 prototype `.active` 為單一真源
before：
```
document.getElementById('web-search-toggle').onclick = () => {
  useWebSearch = !useWebSearch;
  document.getElementById('web-search-toggle').classList.toggle('active', useWebSearch);
};
```
after：
```

  wsBtn.addEventListener('click', () => {
    useWebSearch = wsBtn.classList.contains('active');

```

prototype HTML `web-search-toggle` 預設帶 `active`，使 `useWebSearch` 啟動即
與 UI 一致；屬「讀 prototype 狀態」範圍。）

### 3.2 `#upload-btn` / `#cleanup-btn` / `#logout-btn` — addEventListener + stopImmediatePropagation
三者 `.onclick = …` → `addEventListener('click', (e) => { e.stopImmediatePropagation(); … })`
（對應收尾 `};` → `});`）。before/after（以 upload 為例）：
```
- document.getElementById('upload-btn').onclick = () => {
-   const input = document.createElement('input');
+ document.getElementById('upload-btn').addEventListener('click', (e) => {
+   e.stopImmediatePropagation();
+   const input = document.createElement('input');
    ...
-   input.click();
- };
+   input.click();
+ });
```
cleanup-btn / logout-btn 同模式（各於 handler 首行加 `e.stopImmediatePropagation();`，
`};`→`});`）。

> ⚠ **誠實標註（需 baron 手動驗時注意）**：prototype demo handler 與業務
> handler 同在一個 `<script>`，prototype JS 先執行（先 `addEventListener`
> 註冊），業務後執行（後註冊）。同元素 listener 依**註冊序**觸發 →
> **prototype demo handler 會先跑**，業務的 `stopImmediatePropagation()`
> 在「之後」執行，無法取消「已執行」的 prototype demo。實測預期殘留：
> 點 upload 仍會多開一次 prototype 的空 `confirm-modal`（demo）；點
> cleanup/logout 仍會先跑 prototype demo `customConfirm`。此為決策 3.2
> 所選機制的先天限制（stopImmediatePropagation 只能擋「之後」的 listener，
> 擋不掉「之前已跑」的）。**未自行更動**（不可改 prototype JS）；列此待
> baron 驗 UI 後決定是否需進一步處置（例如改為 capture 階段攔截、或破例
> 移除該幾行 prototype demo handler）。
