## 新增函式（processor/metadata_extractor.py）
- `_STAGE_A_PROMPT`：依設計 Stage A 的 prompt（含「排除章節名/頁碼、不編造、
  從圖判讀 logo 機構、回純 JSON」）。
- `extract_metadata_from_first_page_llm(pdf_path, llm=None)`：
  取第一頁文字(≤4000字)+渲染圖(PNG) → LLM(有圖用 `chat_with_image`，
  無圖 fallback `chat`) → `strip_json_fence` → `json.loads` → `_coerce_llm_meta`
  正規化（缺鍵補 None/[]、authors/keywords 轉 list、date 經 `date_to_iso`）。
  第一頁無文字 / LLM 失敗 / JSON 壞 → None。**永遠 soft fail**。
  `llm=None` 時延遲 import `config.LLMClient` + `settings.LLM_DOC_MODEL`
  （模組載入不需金鑰；測試以注入替身避免打 API）。
- `_coerce_llm_meta`：LLM dict → 固定 flat 結構。
- `fill_from_llm_page1(metadata, llm_meta)`：對稱於 `fill_from_pdf_metadata`，
  source='llm_page1'、confidence='high'，先到先得 + 一律寫 alternates。
- `merge_stage_a(pdf_filled, llm_filled)`：雙來源先決合併——
  皆有且一致→`both_agree`/high；一有一空→用有的/high；衝突→取 LLM/
  `llm_page1 (conflict with pdf_metadata)`/medium；皆空→None/None；
  **abstract 強制空（永遠等 Stage B），LLM abstract 留 alternates**；
  alternates 一律保留兩來源原值。
  正式流程：`A=fill_pdf(empty)`、`B=fill_llm(empty)`、`final=merge_stage_a(A,B)`。

## Edge case / 發現
1. **「補子集」算衝突而非一致**：fitz 抽到部分作者、LLM 抽到完整名單，二者
   normalize 後不相等 → 規則判 conflict → 取 LLM(完整)、confidence=medium。
   結果正確（Mike Tu 補回）但信任度標 medium 而非 high（因兩來源不一致）。
   屬預期且安全（medium 不會誤標為高度確定）；Stage B 之有無不影響此欄已可用。
2. translated_title fitz 無此來源 → 一律走 LLM（one_empty→high），符合
   「一個 LLM call 順便要中文」。
3. 無圖時自動 fallback 純文字 `chat`（domain_detector 一律有圖；本模組更穩健）。
4. 真實 PDF×真實 LLM 測試以 `skipif(not GEMINI_API_KEY)` + 檔案存在檢查雙重保護，
   本環境（output/ 空、無金鑰）skip，**無法在此產出 800-vdc 真實 LLM 結果**；
   需於 OrcStack（有金鑰且有資料）重跑 `test_real_pdf_with_llm` 與 I 節手動指令驗證。
