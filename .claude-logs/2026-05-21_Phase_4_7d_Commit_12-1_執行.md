## 修法

### 1. 新增 `llm/retry.py`（111 行）

兩個 decorator：

- **`retry_call(retries=3, base=2.0)`**：同步 callable
  - 對 retryable exception（5xx / 429 / timeout / connection / unavailable / deadline）退避後重試
  - 對 non-retryable（4xx / ValueError / 其他）立刻 raise
  - 重試用盡時 raise 原例外（型別 / message 不變）
  - 退避：`base * 2**attempt + random.uniform(0, 1)`

- **`retry_stream(retries=3, base=2.0)`**：generator function
  - 僅在「尚未 yield 任何元素前」失敗才重啟（避免重複片段）
  - 已 yield 後失敗直接 raise（不重啟）
  - non-retryable 立刻 raise

- **`_is_retryable(e)`**：依例外 message 字串匹配 retryable token

### 2. 新增 `tests/test_llm_retry.py`（195 行）

12 個測試覆蓋 plan §6.2 設計：

| # | 測試 | 驗證 |
|---|---|---|
| 1 | `test_is_retryable_5xx` | 502 / 503 / 504 應 retryable |
| 2 | `test_is_retryable_429` | 429 應 retryable |
| 3 | `test_is_retryable_non_retryable` | 400 / 401 / ValueError 不 retryable |
| 4 | `test_retry_call_5xx_then_success` | 502 一次後成功、calls=2 |
| 5 | `test_retry_call_4xx_no_retry` | 400 立刻拋出、calls=1 |
| 6 | `test_retry_call_exhausts` | 持續 503、calls=4（retries+1） |
| 7 | `test_retry_call_429_retries` | 429 應重試 |
| 8 | `test_retry_call_non_retryable_value_error` | ValueError 不重試 |
| 9 | `test_retry_call_backoff_timing` | delay 序列 = [2.5, 4.5, 8.5]（jitter 固定 0.5） |
| 10 | `test_retry_stream_pre_yield_retry` | 第一次 yield 前 raise '502' → 重啟成功 |
| 11 | `test_retry_stream_mid_stream_no_retry` | yield 1 個後 raise '502' → 立刻拋出 |
| 12 | `test_retry_stream_non_retryable_no_retry` | ValueError 立刻拋出 |

`FakeCounter` helper：固定失敗 N 次後 return 'ok'，用 `monkeypatch.setattr(time, 'sleep', ...)` 加速 + `random.uniform` 固定 jitter 驗證 timing。
