> v1（`2026-05-21_doc_type_新增手冊_三軸融合.md`）對信任度與融合範圍的判斷有誤，本 v2 修訂；v1 的「Step 1-10 手冊本體 / 註冊點盤點 / 7 doc_type 對照」仍正確、本檔不重複。

## 0. 四個資料源（v1 把 fitz 與 llm_page1 混為一個「metadata 軸」是錯的）

| 縮寫 | 真實來源 | 實作位置 | 信任度特性 |
|---|---|---|---|
| **raw** | MinerU PDF→MD 後、md_processor 抓的第一個 `#` heading + `authors_info` 區塊 | `md_processor.parse()` `result['title']` / `result['authors_info']` | Layout YOLO 對 metadata 區塊弱、TOC/頁編號常被誤抓 |
| **pdf_metadata** | fitz 讀 PDF 內嵌欄位（title / author / creationDate / keywords / subject） | `extract_pdf_metadata()` | **最不可信**——人類匯出 PDF 多半不改、預設值常見垃圾（「Microsoft Office User」「PowerPoint Presentation」「Document1」） |
| **llm_page1** | LLM 看 page 1 文字 + 渲染圖（technical 看頭 3 頁） | `extract_metadata_from_first_page_llm()` | 通常正確；4.7c step 3 後對 resume/technical 有專用 prompt |
| **markdown_extracted** | Stage B 從 MinerU 已轉好的 markdown 抽（**目前僅 abstract 走此路**） | `extract_abstract_from_markdown()` | 可信（abstract 段直接抓文字、不過 LLM 仲裁） |
| **domain** | DomainDetector LLM 看 page 1 文字 + 圖，輸出 10-30 字短句 | `domain_detector.detect()` | **繞過 PDF metadata、直接判主題**；不是欄位來源，是**仲裁者** |
| **doc_type** | 使用者手選 | `_confirmed_doc_type` | 100% 可信，但只是路由 enum、不提供欄位值 |

實作上 `metadata_extractor` 把 `pdf_metadata` / `llm_page1` / `markdown_extracted` 三路結合到同一個 `{value, source, confidence, alternates}` dict，**用 `.source` 區分**——但融合決策必須**逐 source 評估**，不能把它們當同一個「metadata 軸」。

### PART 0 修訂版（domain 合併後）

> baron 觀察 2026-05-21：DomainDetector 與 metadata `llm_page1` **都看 PDF 第一頁文字 + 渲染圖、輸入 100% 相同**（驗證證據：`processor/domain_detector.py:30-49` vs `pipeline_core.py:240-260`、兩者皆走 `chat_with_image`），實際是「一次 LLM call 應該完成兩件事」被拆成兩 call、浪費 2× token / latency / 成本。
>
> 修訂後：**`domain` 不是獨立資料源**，而是 `llm_page1` LLM call 多輸出的一個欄位。

修訂後的資料源表（**取代** §0 上表）：

| 縮寫 | 真實來源 | 實作位置（4.7d Commit 0 之後） | 信任度特性 |
|---|---|---|---|
| **raw** | MinerU PDF→MD 後、md_processor 抓的第一個 `#` heading + `authors_info` | `md_processor.parse()` | 同上 |
| **pdf_metadata** | fitz 讀 PDF 內嵌欄位 | `extract_pdf_metadata()` | **最不可信**——同上 |
| **llm_page1** | **一次** LLM 看 page 1 文字 + 渲染圖（technical 看頭 3 頁），抽**全部 metadata 欄位 + domain** | `extract_metadata_from_first_page_llm()`（Commit 0 後 prompt 多 1 欄 `domain`） | 通常正確；4.7c step 3 doc_type 專用 prompt 仍適用 |
| **markdown_extracted** | Stage B 從 markdown 抽 abstract | `extract_abstract_from_markdown()` | 可信 |
| **doc_type** | user 選 | `_confirmed_doc_type` | 100% 可信 |

說明：
- `domain` 仍是「LLM 看內容生成的主題描述」、語意與其他 metadata 欄位獨立、可作為**融合決策的仲裁者**（§5）——只是技術上來自同一次 LLM call。
- `DomainDetector` class 在 Commit 0 後**保留**為 fallback（若 `metadata['domain'].value` 為空 → 補跑），不刪。
- 既有 paper 無 `metadata.domain` 鍵 → reader 端 optional chain 自然處理（schema 加欄位向下相容）。

**關鍵觀察**：
1. **title / candidate_name 是唯二 raw axis 也供應的「主資料欄位」**——其他欄位 raw 都不出資料，融合決策變單純（哪個 source 有值就用哪個）。
2. **abstract 走獨立路徑**：`markdown_extracted` 是唯一可信來源；`pdf_metadata` 沒此欄位；Stage A merge 強制丟 LLM abstract。
3. **authors 的 raw 來源 `authors_info` 是「自由文字混雜 affiliations」**，需切分；多數 doc_type（slides/technical/web/news）甚至 raw 沒抽到。

### PART 1 修訂版（domain 併入 llm_page1）

修訂後的供給矩陣（**取代** §1 上表的最右「domain」欄）：原表「domain」欄全部 `⚪`、僅「`domain` 欄位列」於 `llm_page1` 標 🟢——加入此新列即可、其餘列保持不變。

| 欄位 | raw (first-#) | raw (authors_info) | pdf_metadata | llm_page1 | markdown_extracted |
|---|---|---|---|---|---|
| **domain**（新） | ⚪ | ⚪ | ⚪ | 🟢（Commit 0 後 prompt 多此欄；fallback：`DomainDetector` 補跑） | ⚪ |

說明：
- 原表「domain 軸」這一**整欄**刪除，所有欄位不再以 `domain` 作獨立 source。
- `domain` 改為**一個欄位**、由 `llm_page1` 一次性產出；用途仍是 §5 仲裁。
- `markdown_extracted` 對 domain 不出資料（domain 設計上看封面、不抽正文）。

**關鍵觀察補充**：
4. **Commit 0 後 LLM call 數減半**：原本 pipeline 跑 1 次 metadata LLM call + 1 次 domain LLM call（input 相同）→ 合併為 1 次。token / latency / 成本 -50%。
5. **`DomainDetector` 不刪**：作為 fallback；若 `metadata['domain'].value` 為空 → 補跑（理論上極少觸發、只當 4.7d Commit 0 prompt 更新失敗時的安全網）。

## 2. 信任度模型（細到 source 層級）

### 2.1 metadata.source 內部信任度（grep 確認真實值）

依 `metadata_extractor.py` 程式碼，`metadata.{field}.source` 可能值：

| source 標籤 | 來源 | 信任度 | 為什麼 |
|---|---|---|---|
| `pdf_metadata` | fitz 抽 PDF 內嵌欄位 | **🔴 最低** | PowerPoint 匯出 → 「Microsoft Office User」；Word 匯出 → 「Document1」；只有刻意設定的 LaTeX academic 較可信 |
| `llm_page1` | LLM 看 page 1 抽 | **🟢 高** | 直接看視覺與文字、繞過 metadata 污染 |
| `both_agree` | pdf_metadata 與 llm_page1 norm 後相等 | **🟢🟢 最高** | 雙路一致 = 雙重確認 |
| `llm_page1 (conflict with pdf_metadata)` | merge_stage_a 衝突取 LLM | **🟡 中** | LLM 較可信但兩源不一致 → 警號 |
| `markdown_extracted` | Stage B 從文章內 abstract 段抓 | **🟢 高** | 從正文抓、不依賴 metadata |
| `manual` | （目前未用、保留）| **🟢 最高** | user 手動覆寫 |

### 2.2 raw（MinerU）信任度按 doc_type × 欄位

| doc_type | raw title | raw authors_info |
|---|---|---|
| academic | 🟢 通常 = title | 🟡 通常有但需切 affiliations |
| book | 🟢 | 🔴 通常沒抽到（書無 authors 區塊在頁首） |
| technical | 🔴 cover-TOC → 「Contents」 | 🔴 通常沒 |
| news | 🟢 | 🟡 byline 可能在 |
| web | 🟡 視站台 | 🔴 通常沒 |
| resume | 🟢 候選人姓名 | 🟡 可能是聯絡資訊塊 |
| slides | 🔴 「## 第 N 頁」 | 🔴 SlidesProcessor 不抽 |

### 2.3 三源真實信任度排序（條件式，不是線性）

**v1 錯把「metadata 軸」當單一線性大於 raw**。**v2 修正**：

1. **`both_agree` > 任何單源** —— 雙路確認、最強
2. **`llm_page1` > `pdf_metadata`** —— LLM 看內容、PDF metadata 容易被預設值污染
3. **`raw` vs `llm_page1`**：兩者 norm 一致 → 取 `llm_page1`（語意更明確、含 translated_title）；不一致時看是否在黑名單 + domain 仲裁
4. **`raw` vs `pdf_metadata`**：**raw 通常勝**（除非 raw 在黑名單）；因為「99% 人沒改 PDF metadata」（baron 觀察）、raw 至少是 PDF 內文渲染出來的
5. **`markdown_extracted` 對 abstract 是唯一可信**——其他 source 此欄要不沒有、要不被強制丟

## 3. 黑名單規則

### 3.1 Title 黑名單

```python
TITLE_BLACKLIST_EXACT = {
    # 章節 label（中英）
    "contents", "table of contents", "目錄", "目次",
    "abstract", "摘要", "summary", "executive summary",
    "introduction", "前言", "緒論", "intro",
    "references", "参考文献", "參考文獻", "bibliography",
    "acknowledgements", "acknowledgments", "致謝",
    "appendix", "附錄",
    "preface", "序",
    # PDF 匯出器預設
    "untitled", "untitled document", "untitled1",
    "document", "document1", "document2",
    "未命名", "未命名文件",
    "powerpoint presentation", "slide 1", "slide1",
    "presentation",
    # 履歷 label
    "resume", "cv", "curriculum vitae", "履歷", "個人簡歷",
}
TITLE_BLACKLIST_PATTERN = [
    r"^第\s*\d+\s*頁$",         # 第 N 頁
    r"^page\s*\d+$",
    r"^chapter\s*\d+$",         # Chapter N
    r"^第\s*\d+\s*章$",
    r"^slide\s*\d+$",
    r"^section\s*\d+$",
    r"^\d+$",                   # 純數字（如「1」「2」）

]
```

判斷流程：`title.strip().casefold()` 後做 `EXACT` set 查詢 + 對每個 `PATTERN` 試 match。

## 4. 窮舉決策樹（每欄位逐狀況）

### 4.1 Title 決策樹（25 種狀況）

符號約定：
- **R** = raw（md_processor.first-#）
- **M** = metadata.title.value
- **MS** = metadata.title.source（pdf_metadata / llm_page1 / both_agree / llm_page1 (conflict ...) ）
- **CN** = metadata.candidate_name.value
- **OFN** = original_filename
- **sim(a,b)** = 4.6 相似度判斷（true / false）
- **bl(s)** = s 在黑名單中
- **dom_match(s, domain)** = 5.1 domain 仲裁（true / false / N/A）

| # | doc_type | R | M | MS | CN | 條件 | 取值 | 信心度 | 備註 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | resume | any | any | any | 有 | — | **CN** | high | doc_type 短路 |
| 2 | resume | 有 | 空 | — | 空 | bl(R)=否 | R | medium | 履歷無 candidate_name 抽到、raw 是姓名 |
| 3 | resume | 空 | 空 | — | 空 | — | OFN→paper_uuid | low | 全失敗 |
| 4 | any | 空 | 空 | — | — | — | OFN→paper_uuid | low | 全失敗 fallback |
| 5 | any | 空 | 有 | any | — | bl(M)=否 | M | high | 唯一來源 |
| 6 | any | 空 | 有 | any | — | bl(M)=是 | OFN→paper_uuid | low | metadata 也雜訊 |
| 7 | any | 有 | 空 | — | — | bl(R)=否 | R | medium | 唯一來源（保守取 raw） |
| 8 | any | 有 | 空 | — | — | bl(R)=是 | OFN→paper_uuid | low | raw 雜訊、metadata 也無 |
| 9 | any | 有 | 有 | both_agree | — | bl(R)=否 | M | high | 雙路一致、用較規範的 metadata |
| 10 | any | 有 | 有 | both_agree | — | bl(R)=是 | M | medium | 兩者一致但都疑似雜訊（少見）；仍取 metadata |
| 11 | any | 有 | 有 | llm_page1 | — | sim(R,M)=true | M | high | LLM 改善版本（如多出副標）、可信 |
| 12 | any | 有 | 有 | llm_page1 | — | sim(R,M)=false, bl(R)=是 | M | high | raw 雜訊（TOC / 頁碼）、LLM 勝 |
| 13 | any | 有 | 有 | llm_page1 | — | sim(R,M)=false, bl(R)=否 | **domain 仲裁**（見 §5.2） | medium | 兩者都看似合法但不同 → domain 決勝 |
| 14 | any | 有 | 有 | pdf_metadata | — | sim(R,M)=true | M | medium | PDF 與 raw 一致、難得；用 metadata 較規範 |
| 15 | any | 有 | 有 | pdf_metadata | — | sim(R,M)=false, bl(R)=否 | **R** | medium | **99% PDF metadata 是垃圾、raw 勝**（baron 觀察） |
| 16 | any | 有 | 有 | pdf_metadata | — | sim(R,M)=false, bl(R)=是 | M | medium | raw 黑名單、雖然 metadata 不可信但只能用它 |
| 17 | any | 有 | 有 | llm_page1 (conflict ...) | — | sim(R,M)=true | M | medium | 不太可能（衝突反而與 raw 同）、取 metadata |
| 18 | any | 有 | 有 | llm_page1 (conflict ...) | — | sim(R,M)=false, bl(R)=否 | **domain 仲裁** | medium | LLM 與 PDF 矛盾、看 domain |
| 19 | any | 有 | 有 | llm_page1 (conflict ...) | — | sim(R,M)=false, bl(R)=是 | M | medium | raw 黑名單、LLM 勝 |
| 20 | any | 有 | 有 | manual | — | any | M | high | user 手動設、最終 |
| 21 | technical | 「Contents」/「目錄」 | 有 | llm_page1 | — | — | M | high | 13/15 的特化（black-list 明確） |
| 22 | slides | 「第 1 頁」/「Slide 1」 | 有 | llm_page1 | — | — | M | high | 同上 |
| 23 | slides | 「第 1 頁」/「Slide 1」 | 空 | — | — | — | OFN→paper_uuid | low | slides metadata 失敗、退到檔名 |
| 24 | any | 有 | 有 | — | — | sim(R,M)=false 且 bl(R)=否 且 dom_match 都失敗 | **R** | low | 全 fallback 仍取 raw（保守） |
| 25 | any | — | — | — | — | resolve 結果為 paper_uuid | log warning + return paper_uuid | low | 最終 fallback、log 警示 |

注意：#15 是 **v1 寫錯的關鍵點**——v1 把 metadata 一律置頂，但 metadata.source = pdf_metadata 時 raw 應勝。

### 4.2 Authors 決策樹

維度：raw 通常只在 `authors_info`（自由文字塊）；metadata 來源以 LLM 為主。

| # | raw.authors_info | metadata.authors.value | MS | 條件 | 取值 | 備註 |
|---|---|---|---|---|---|---|
| 1 | 空 | 空 | — | — | **省略 authors 行** | 多數 doc_type（slides/book/web/resume）正常情形 |
| 2 | 空 | 有 | llm_page1 / both_agree | bl(M)=否 | M | LLM 抽到 |
| 3 | 空 | 有 | pdf_metadata | 整陣列 in 黑名單 | 省略 | 「Microsoft Office User」等垃圾 |
| 4 | 空 | 有 | pdf_metadata | 整陣列 in 黑名單=否 | M | PDF metadata 偶有正確（LaTeX）|
| 5 | 有 | 空 | — | — | **保留 authors_info 段**（沿用 md_restore 既有路徑） | 後 fallback；切 affiliations 由既有 `_clean_authors_info` 處理 |
| 6 | 有 | 有 | llm_page1 / both_agree | M 在黑名單=否 | **M**（結構化陣列）+ 丟 raw.authors_info | LLM 已切好作者 |
| 7 | 有 | 有 | pdf_metadata | 整陣列 in 黑名單 | 保留 raw.authors_info | M 是垃圾、raw 是文字塊 |
| 8 | 有 | 有 | pdf_metadata | bl=否 | 看相似度：sim true→M；sim false→raw | PDF 偶爾正確；但 raw 是頁面實際印的 |

`bl` 對 authors 採「單條目剔除 + 整陣列查」雙模式。

### 4.3 Publication Date 決策樹

特殊：`pdf_metadata.publication_date` **實際上是 creation_date**（PDF 製檔日，**非**發表日）。

| # | M | MS | 條件 | 取值 | 備註 |
|---|---|---|---|---|---|
| 1 | 空 | — | — | 省略 | 多數 doc_type 正常 |
| 2 | 有 | llm_page1 / both_agree | bl(M)=否（非 1970-01-01 / 未來年）| M | LLM 抽文章內標示日期 |
| 3 | 有 | llm_page1 / both_agree | bl(M)=是 | 省略 | 異常日期、丟棄 |
| 4 | 有 | pdf_metadata | — | **省略 publication_date 行；若需「製檔日」可寫進 alternates，不寫入 header** | PDF metadata 永遠是 creation_date、不可當發表日 |

特例：若 `MS == both_agree` 但兩值同（都是 1970-01-01）→ 仍走 #3 黑名單路徑。

### 4.4 Abstract 決策樹

特殊：
- raw 沒有獨立 abstract 欄位（在 `data['sections']` 內找 `type == 'abstract'`、其 `content[0]['content']` 為英文 abstract、`content[0]['translated_content']` 為中文）

## 5. Domain cross-check 仲裁邏輯

domain 是「**仲裁者**」（v1 把它當 sanity check 是錯）——當決策樹某些狀況「兩源都看似合法但不同」（4.1 #13、#18）才動 domain；不在每欄位都跑。

### 5.1 「value 跟 domain 是否相符」判斷

| 步驟 | 動作 |
|---|---|
| 1 | `domain` 字串切 token：以「-」「：」「、」「,」空白為界，去停用詞（中：的/與/和；英：of/and/the/in/for） |
| 2 | `value` 字串同樣切 token、casefold |
| 3 | 計算共同 token 數：set 交集 |
| 4 | 規則：交集 ≥ 1 → 相符；= 0 → 不相符 |
| 5 | 邊界：domain 為空字串 → 一律「N/A」（不進仲裁） |

**純規則式、不上 LLM**——降成本、可預期、log 友善。

範例：
- domain = `"電力電子技術 - 高壓直流系統架構"` → tokens `{電力電子技術, 高壓直流系統架構}`（中文以分隔符切，未做斷詞）
  - 為提升交集機率，**中文 token 額外拆 2-gram / 3-gram**：`{電力, 力電, 電子, 子技, 技術, 高壓, 壓直, 直流, 流系, 系統, 統架, 架構, …}` plus 整字串
  - value = `"800-VDC Architecture for AI Infrastructure"` → tokens `{800, vdc, architecture, ai, infrastructure}`
  - 交集 = ∅（中英文混合難對到）
  - **改進**：domain 通常含英文 → 把 domain 內出現的英文 token 也獨立切（regex `[A-Za-z][A-Za-z0-9-]*`）+ 中文 2/3-gram；value 端做相同處理
  - 這樣 `"高壓直流"` ↔ `"800-VDC"` 仍交集為 ∅、但 `"AI Infrastructure"` ↔ domain 含 `"AI"` token（若 domain 是英文形式）會中

**邊界誠實**：純規則式對「中文 domain ↔ 英文 title」會誤判 false。**緩解**：
1. domain prompt 改要求「同時給中英關鍵字 2-3 個」（屬下次調整）
2. 仲裁失敗時 fall back 「raw 勝」原則（保守）

### 5.2 仲裁規則（用於 4.1 #13、#18）

```
INPUT: raw R, metadata M, domain D
arb_R = dom_match(R, D)    # bool
arb_M = dom_match(M, D)
RULES:
  arb_M=true  + arb_R=true   → 取 M（兩者皆符；M 較規範）
  arb_M=true  + arb_R=false  → 取 M
  arb_M=false + arb_R=true   → 取 R
  arb_M=false + arb_R=false  → log warning + 取 R（保守取 raw、避免 LLM 假陽性蓋掉真資料）
  D=空（domain 失敗）        → 不進仲裁、外層直接走 #15 規則（raw 勝；除非 raw 黑名單）
```

## 6. 相似度判斷實作

| 方式 | 優 | 劣 | 結論 |
|---|---|---|---|
| 字面包含 `a in b or b in a` | 0 依賴、O(n)、最快 | 無法處理「AlphaFold-2」vs「AlphaFold」差一個字尾的場景 | 太弱 |
| `difflib.SequenceMatcher.ratio()` | stdlib、無依賴、句長相當穩定 | O(n²)；中英混合不一定準 | ✅ **推薦** |
| 語意相近（embedding） | 強健 | LLM/embedding 成本、慢 | 不建議——成本/效益不划算 |

**推薦規則**：
```python
def title_sim(a: str, b: str) -> bool:
    if not a or not b: return False
    A = re.sub(r"\s+", "", a).casefold()
    B = re.sub(r"\s+", "", b).casefold()
    if A == B: return True
    if A in B or B in A: return True
    from difflib import SequenceMatcher
    return SequenceMatcher(None, A, B).ratio() >= 0.7
```

`title_sim` 三段：完全相等 / 包含關係 / 編輯距離比率 ≥ 0.7。實證 0.7 是 title 類短字串的合理閾值（學術論文 title 改一兩個字 ratio 約 0.85–0.95、完全不同 < 0.4）。

不同欄位閾值可微調：
- title / candidate_name：0.7
- authors（單一條目比對）：0.85（姓名容錯空間小）
- abstract：不做相似度（一律取 markdown_extracted）
