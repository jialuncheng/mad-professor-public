## §1 TL;DR（概要）

- **挑戰**：前端主題下拉選單為靜態寫死，自訂主題僅存 JS 閉包記憶體；頁面 Reload 後自訂主題清單全部丟失（除 localStorage 還原的單一當前主題外），選單退回原始四項。
- **解法**：
  1. C1：後端 `web_server.py` 新增 `GET /api/themes` 動態掃描 `static/themes/`，回傳含 `custom`/`updated_at` 欄位的 JSON 列表；同步修正 `tests/test_themes_upload.py` fixture 未掛載 GET 端點的盲點，並新增 `test_list_themes_endpoint`。
  2. C2：前端 `static/index.html` 新增 `dropdownAPI.setThemes()` 動態覆寫介面、`setupOne` 分組分隔線視覺、`loadThemesFromServer()` 非同步載入函式（頁面初始化呼叫 + 上傳成功後呼叫）。
- **影響範圍**：FE-Refactor（`static/index.html`）+ BE-Refactor（`web_server.py`）混合；既有 Paper/Folder/Chat/RAG/DB 模組 100% 不動；零 schema 變動。
- **不可動清單**：見 §7

## §4 設計方案

### §4.1 C1 — 後端主題清單 API + 測試 fixture 修正

`web_server.py`：在現有 `upload_theme` 函式結尾後（確認為 `return {...}` 之後）新增 `list_themes()` 函式，路由 `GET /api/themes`。邏輯：先插入 4 個內建主題（`custom=False, updated_at=0.0`），再掃描 `BASE_DIR / "static" / "themes"` 目錄取得所有 `.css` 後綴檔案，排除 built-in 檔名，對剩餘自訂主題讀取 `st_mtime` 並加入結果。

`tests/test_themes_upload.py`：在 fixture 中於 `app.post("/api/themes/upload")(web_server.upload_theme)` 行之後，緊接新增 `app.get("/api/themes")(web_server.list_themes)`。在現有測試後新增 `test_list_themes_endpoint` 測試。

### §4.2 C2 — 前端主題選單動態載入

`static/index.html` 四項變更（全以 grep 動態定位行號，不依賴計畫書行號）：
1. **setThemes() 介面**：在 `getThemeLabel(name) { ... },` 行之後、`};` 返回物件結束之前，插入 `setThemes(themesList)` 方法。
2. **setupOne 分組分隔線**：在 `setupOne` 函式內的 `items.forEach(([val, label]) => {` 開括弧右側第一行插入 `hasCustomHeader` 旗標邏輯，在非內建主題首次出現時渲染分隔線 div 與「自訂主題」label div。
3. **loadThemesFromServer()**：在 `if (savedTheme) { ... }` 區塊之後，以 async function 宣告完整的 `loadThemesFromServer()` 並在宣告後立即呼叫 `loadThemesFromServer()`。
4. **upload handler 更新**：在上傳成功 handler 內，找到 `dropdownAPI.addTheme(themeName)` 及其後的 dropdown 顯示更新三行（`const dd = ...`、`dd.dataset.value = ...`、`dd.querySelector(...).textContent = ...`），全部替換為 `await loadThemesFromServer()`，並刪除 BUG-F2 A5 的舊 comment。
