## 真因

baron 想用 `logs/pipeline.log` 分析各 paper 各 stage 耗時、作為未來改善 baseline。

問題：並發跑多份 paper 時、`[stage] X 完成 耗時=Ys` 訊息**沒帶 paper_id**——無法歸屬到正確 paper。本 commit 為所有 stage 相關 log 加 `{paper_id}` 前綴，讓未來分析腳本能精準歸屬。

---

## 修法

### 1. `pipeline_core.process()` 早一步決定 `pid`

```python
pid = paper_id if paper_id is not None else pdf_path.stem
self.paper_info['paper_id'] = pid   # 提前到 metadata Stage A 之前
```

`pid` 同時作為**所有 stage log 的前綴**。helpers（`_check_stage_exists` / `_stage_detect_domain`）走 `self.paper_info.get('paper_id')` 取（時序上保證已設）。

### 2. 共 40 處 log 加 paper_id 前綴

涵蓋：
- **`[pipeline]`**：開始 / 進入 stage loop / 準備寫 DB / DB 寫入完成 / 全部完成
- **`[metadata]`**：Stage A 開始 / fitz 完成 / LLM 第一頁完成 / Stage A 完成 / Stage A 合併完成 / Stage A 失敗 / Stage B 開始 / Stage B 完成（雙處）/ Stage B 失敗
- **`[stage]`**：開始 / 完成 耗時 / 失敗 耗時（含 sequential + 並行兩條路徑）
- **`[並行]`**：完成（耗時）/ 失敗（耗時）
- **`並行執行: ...`**：analyze + detect_domain / translate + image_caption
- **`階段 X ...`**：完成 / 失敗 / 已存在跳過（5 處）
- **`[domain]`**：從 metadata.domain 取得 / fallback / 失敗
- **`未知的處理階段` / `開始運行階段` / `簡報類型，使用 Vision 解析`**：3 處

`grep -c "{pid}\|{_pid}\|{self.paper_info.get('paper_id')}" pipeline_core.py` = **40 處**。
