## §4 修法說明（含設計取捨）

### §4.1 廢 lifespan preload + chat 按需 Lazy Load（`web_server.py`）
- lifespan L220 `preload_vector_stores` 呼叫以 C3 註解塊取代（保留錨點說明）。
- **chat 端點**（`db_id` 404 檢查後）加守衛：`if (uid, paper_id) not in ai_core._paper_cache: paper_manager.load_paper_resources(...)`——使用者發起 RAG 問答時才動態加載；被 LRU 淘汰後再問答於此重載。**此守衛為廢 preload 的必要配套**（否則跨 session 啟動後快取為空、chat 將全 cache-miss）。

### §4.2 `rag_retriever.py` — vector_stores LRU（FAISS 記憶體大宗）
`vector_stores` 改 `OrderedDict`；`_evict_vector_lru()`（`while len>RAG_MAX_CACHE: popitem(last=False)+gc.collect()+log`）；`add_paper` 插入後 / `_get_vector_store` 命中或惰性重載後 `move_to_end` + evict。
- **設計取捨（保證 retrieve 正確性）**：僅 `vector_stores`（FAISS、記憶體大宗）採 LRU 淘汰；`paper_vector_paths`（路徑字串、極輕）與 `rag_trees`（JSON、輕）**不淘汰**——確保 FAISS 被淘汰後可由 `paper_vector_paths` 惰性重載、且 `retrieve_*` 永遠取得到對應 `rag_tree`（避免兩快取淘汰不同步致 `retrieve_with_context` 在 L103-104 回空）。
- **`retrieve_with_context` / `retrieve_multi_with_context` 演算法本體未動**（僅 `_get_vector_store` 取快取處加 move_to_end）。

### §4.3 `ai_core.py` — _paper_cache LRU（RAG cache）
`_paper_cache` 改 `OrderedDict`；`query_stream` 命中 `move_to_end`；`load_paper_cache` 插入後 LRU 淘汰（`popitem(last=False)+gc.collect()+log`）。

```python
# rag_retriever._evict_vector_lru
while len(self.vector_stores) > RAG_MAX_CACHE:
    _ev_key, _ = self.vector_stores.popitem(last=False); gc.collect()
    logger.info(f"[lru] 向量庫淘汰最久未使用: {_ev_key}")
```

### §4.4 `tests` — C3 測試（2 項）
`test_lru_vector_store_eviction`（6 paper 載入 → 上限 5、p0 淘汰、paper_vector_paths 全留、move_to_end 保活躍）/ `test_lru_evicted_vector_lazy_reloads`（淘汰後 `_get_vector_store` 經 paper_vector_paths 惰性重載成功）。
