## 3. 真因分析

### Bug 1 為什麼 R2 ship 時 tag 重整後消失？
- R2 (Phase 1) 寫 tag → `set_paper_tags` 寫 SQLite metadata_json，API `_to_dict` 回 `'metadata'` key。
- 前端 R2 tag-pill 渲染、tag-modal 載入只讀 `p.metadata_json.user_tags`。
- API shape ≠ 前端讀取 key → 首次載入 tag-pill 空、user 手動存一次後因 L1873 寫入 `p.metadata_json`、in-memory 才暫時可見。
- 重整即消失。BUG-F1 fallback chain + 雙寫補完此 R2 漏洞、跟 P2-3 collectAllUserTags 同 pattern。

### Bug 3 為什麼 `；` 不能斷行？
- HTML attribute 內全形分號 `；` 是字元、不是換行；CSS `content: attr(data-placeholder)` 預設 `white-space: normal`、collapse whitespace。
- 真正換行需 `&#10;`（HTML 實體）或 `\n`（JS 字面）+ CSS `white-space: pre-wrap`。
- `min-height: 56px` 預留兩行高度、避免 user 開始 type 時容器突然縮小。

### Bug 4 為什麼 CSS 蓋不過 inline style？
- CSS Specificity：inline style > id selector > class > element。
- enableChat 用 `style.display = 'block'` 寫 inline、優先級遠超 `.collapsed > ... > :not(#chat-toggle)` selector。
- `!important` 是唯一能蓋過 inline 的方式（除非用 `style.removeProperty('display')`、但 JS 重構成本高）。

### Bug 5 為什麼主題系統 v2 重構先做？
- v3 Q4 原計畫「方案① width:100% 先 ship、方案② 留主題系統重構」；ui-fixes-batch B7 提供完整 `--content-max-w` token 方案、一次到位、不留二次施工。
- 此 token 抽出讓 toolbar + paper-content + abstract 三者共軌、寬螢幕對稱（過去 toolbar 邊距 16px / paper-content 自動置中、視覺破裂）。
- 4 主題各自保留原 max-width 數值（kahn 720 / nara 800 / kandinsky 820 / mies 860）、只是改用 token 集中管理、零視覺變動。
