## §4 修法說明

### §4.1 WORKFLOW_SOP.md §3 強制規則補充（r11 對齊）

**新增一行於 §3 強制規則末尾**：
```
- 階段 2 同步更新 TODO.md：拆 tasks 同時，在 TODO.md 新增任務條目並設狀態 🟡 WIP
```

Plan r11 明定「在拆分 tasks 文件的同時，必須同步更新根目錄的 TODO.md」。C1 寫 WORKFLOW_SOP.md 時，§3 六階段流程的 `階段 2` 已含「+ 同步 TODO.md」，但 **強制規則** 段落未補入對應的明文規範，導致 grep 驗收 A 需要「同步更新.*TODO.md」才能命中。

### §4.2 CLAUDE.md §1.4 TODO 維護補充（r11 對齊）

**新增一行於 §1.4 最前**：
```
- 拆 tasks 時同步更新：於 TODO.md 新增任務條目、設 🟡 WIP（per WORKFLOW_SOP §3 階段 2）
```

原 §1.4 僅描述 ship 後的 WIP→完成同步，缺少「拆 tasks 時同步新增條目」的流程邊界。補入後明確三個 TODO 時機：①拆 tasks 時（新增條目）→ ②ship 後（WIP→done）→ ③收官後（歸檔）。

CLAUDE.md 行數：158 → 160 行（≤ 200 ✓）

### §4.3 PROJECT_PROGRESS_CONTROL_FRAMEWORK.md §9.2 更新

**§9.2 重點行**由：
```
重點：plan → tasks → 驗證 → 執行 OP-N → 驗證執行 → 收官；嚴禁跨階段。
```
改為：
```
重點：plan → tasks（+同步更新 TODO.md）→ 驗證 → 執行 OP-N → 驗證執行 → 收官；嚴禁跨階段。
```

使 framework §9.2 的摘要與 WORKFLOW_SOP.md §3 六階段鏈的 r11 規格保持一致。
