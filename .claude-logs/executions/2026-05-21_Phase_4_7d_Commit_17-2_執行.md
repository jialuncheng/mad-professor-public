## 修法

### 1. broker 結構（web_server.py 內、不另起新檔）

```python
@dataclass
class StreamSession:
    owner_id: int
    paper_db_id: int
    paper_uuid: str
    query: str
    chunks_buffer: List[str] = field(default_factory=list)
    grounding_sources: List[dict] = field(default_factory=list)
    subscribers: List[asyncio.Queue] = field(default_factory=list)
    done: bool = False
    error: Optional[str] = None
    started_at: float = field(default_factory=time.time)

active_streams: Dict[Tuple[int, int], StreamSession] = {}
streams_lock = asyncio.Lock()
```

### 2. `_broadcast(session, chunk)`

廣播給所有 subscribers、queue full 時 `put_nowait` 拋 `QueueFull` → log warning + drop（partial 在 `chunks_buffer` 仍完整、後續 attach 拿得到）。

### 3. `_run_stream_background(session, history, visible_content, use_web_search)`

背景 task：
- 用 `asyncio.to_thread(next, gen, _SENTINEL)` 跑 sync generator（同 17-1b 手法、不卡 event loop）
- 每 chunk 寫 `chunks_buffer` + broadcast
- `try/except`：失敗時設 `session.error`、broadcast `'(生成失敗) ...'` 訊息
- `finally`：寫 DB（17-1 邏輯）+ 從 `active_streams` 移除

### 4. `_pump_to_client(session, sub_q)` (async generator)

- **先回放** `chunks_buffer`（給 late attach；sender 第一次 buffer 還空、不回放重複）
  - replay chunks 標 `'replay': True` flag 給前端分辨
- 再從 `sub_q` `asyncio.wait_for(timeout=120s)` read 新 chunks
  - 120s 沒新 chunk + session.done → break（保險、避免永久卡）
- `finally`：從 `session.subscribers.remove(sub_q)`

### 5. `POST /api/papers/{id}/chat` 改造

```python
async with streams_lock:
    # Q1：拒絕同 paper 並發
    if key in active_streams and not active_streams[key].done:
        raise HTTPException(409, "已有進行中的對話、請等待目前對話完成")

    # 17-1 邏輯：進入即寫 user query
    paper_manager.append_chat_message(db_id, user.id, 'user', request.query)
    history = paper_manager.load_chat_history(db_id, user.id)

    session = StreamSession(...)
    active_streams[key] = session

    # sender 為第一個 subscriber（與 attach 對稱）
    sub_q = asyncio.Queue(maxsize=200)
    session.subscribers.append(sub_q)

asyncio.create_task(_run_stream_background(session, history, ...))
return StreamingResponse(_pump_to_client(session, sub_q), media_type="text/event-stream")
```

### 6. `GET /api/papers/{id}/chat/attach`（新 endpoint）

```python
async with streams_lock:
    session = active_streams.get(key)
    if session is None or session.done:
        raise HTTPException(404, "無進行中的對話")
    sub_q = asyncio.Queue(maxsize=200)
    session.subscribers.append(sub_q)
return StreamingResponse(_pump_to_client(session, sub_q), ...)
```

### 7. `GET /chat/history` 加 in_progress（向下相容設計 (c)）

```python
messages = paper_manager.load_chat_history(db_id, user.id)
async with streams_lock:
    session = active_streams.get(key)
    if session is not None and not session.done:
        in_progress = {'query': session.query, 'partial': ''.join(session.chunks_buffer)}

# 向下相容：無 in_progress 時回舊 list；有則回 dict
return messages if in_progress is None else {'messages': messages, 'in_progress': in_progress}
```

**為何選設計 (c)**：避免 17-3 前端未落地時破壞既有 `history.length` 邏輯——舊邏輯收 list 仍正常；只有 stream 進行中才回新格式（這個 case 前端未支援也只是看不到 partial、不會炸）。

## asyncio.Queue + lock 並發陷阱分析（plan §7 落實）

### 陷阱 1：deadlock（subscriber 沒消費 → broadcast 卡）
**緩解**：`put_nowait` 非阻塞 + try/except QueueFull → drop chunk + log warning。**不 await put**。

### 陷阱 2：race（active_streams 讀寫衝突）
**緩解**：所有讀寫都在 `async with streams_lock:` 內。
- chat endpoint：檢 409、append、創 session、加 subscriber
- attach endpoint：檢 session 存在、加 subscriber
- run_stream_background.finally：pop session
- chat/history：read session 狀態快照

### 陷阱 3：queue overflow（client 連線慢 / 中斷沒清 subscriber）
**緩解**：
- `maxsize=200`（合理上限；典型對話 < 100 句）
- `_pump_to_client` finally 移除 sub_q
- `asyncio.wait_for(timeout=120s)`：120s 無新 chunk + done → break

### 陷阱 4：background task 例外被吞
**緩解**：`_run_stream_background` 整段 try/except/finally，error log + 廣播 error chunk + finally 寫 DB + 清 session。

### 陷阱 5：StopIteration 跨 asyncio.to_thread（同 17-1b 已解）
**緩解**：`next(gen, _SENTINEL)` 用 sentinel object 取代 StopIteration。
