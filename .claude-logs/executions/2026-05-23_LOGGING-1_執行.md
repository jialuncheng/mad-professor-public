## §4 真因

依評估報告 v4 §4.3 + §4.8-4.19：

1. **plan §4.13 v3 陷阱 1**：Python `LogRecord` 預置欄位不含 `asctime`（dynamic、由 `Formatter.usesTime()` 或顯式呼叫 `self.formatTime()` 才綁定）；提案原始 `ConsoleFormatter.format()` 直接讀 `record.asctime` 會 100% 啟動崩潰
2. **plan §4.14 v3 陷阱 2**：Uvicorn 預設 `log_config=LOGGING_CONFIG` 會在啟動最後階段 `dictConfig` 覆蓋 root logger handlers、把 `setup_logging()` 配置整個吃掉
3. **plan §4.8 logging 設定不對齊 env override 風格**：既有 `_setup_logging` 內 `log_dir / level / format / max_bytes / backup_count` 全寫死、跟 settings.py 12+ env 風格不對齊
4. **plan §4.9 補強 1**：pytest 230 tests re-import / dev reload 可能撞 `_setup_logging()` 多次、handler 重複掛載印 N 次
5. **plan §4.10 補強 2**：uvicorn / sqlalchemy 預設 handler 跟 root 不一致、stdout JSON + plain 混雜壞雲原生 parser
6. **plan §4.17 v4 建議 1**：INFO 模式下 `sqlalchemy.engine` 逐 SQL 印；MODEL-8 backfill 10 本書 ~500-2000 SQL spam
7. **plan §4.18 v4 建議 2**：ContextVar 無 default、CLI（`tools/regen_rag.py`）/ pytest / 背景任務無 middleware set → `.get()` 拋 LookupError → Formatter 崩潰被吞、日誌完全失去
8. **plan §4.19 v4 建議 3**：`datetime` / `set` / `Decimal` / Pydantic / SQLAlchemy ORM instance 直接 `json.dumps` 拋 TypeError → 退化純文字
9. **plan §4.12 + v3 建議 1**：exc_info 結構化提升 Loki / ELK query 體驗、空 tuple 安全防衛防靜默吞噬
