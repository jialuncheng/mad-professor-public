### §1.1 SessionEnd 能否 block —— 裁決（plan §9 Q2 定案）

**裁決：SessionEnd hook 不能 block / 不能阻止 session 終止。** → DIRTY-RESET 採 **Observable Fault Only**（plan §9 Q2 路徑 B）。

**依據（權威，非記憶）**：Claude Code 官方 hooks 文件「Decision Control by Event」表**未列入 SessionEnd**；SessionEnd 僅出現於 Hook Lifecycle 作為 notification/cleanup 事件。回傳 exit 2 或 `{"decision":"block"}` 對終止**無效**，session 照常結束。具 blocking 能力者僅 `PreToolUse` / `Stop` / `UserPromptSubmit` 等。

**為何不做 in-harness live 實驗（誠實限制）**：Claude Code hook 於 session 啟動時自 settings.json 載入，無 mid-session 重載保證；且要真正觀察「結束被擋」必須結束**當前** session → 無法回報。故 in-harness live block 測試於本 session 結構上不可行，裁決改以官方文件為據（§1.7 證據級別：官方文件 > flaky 自測）。若 baron 仍要 live 驗證，須於**新 session** 掛臨時 SessionEnd hook 後關閉觀察（屬 baron 運維、非 commit）。

### §1.2 附帶修正發現（影響 C4/C5，須回灌 tasks §8）

> 這兩點是 gate 的額外產出，若不修，C4/C5 會照 tasks 現有錯誤描述實作。

1. **🔴 blocking 機制是「exit 0 + JSON」，不是「exit 2」**。tasks §8 C4 寫「deny（例如 exit 2）」**有誤**。官方文件：exit 2 僅把 stderr 當通知、**不 block**。正確機制：
   - **PreToolUse deny**（C4 截斷守衛）：exit **0** + stdout JSON
     `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"..."}}`
   - **Stop block**（若 C5 改 Stop 路線）：exit **0** + `{"decision":"block","reason":"..."}`
   - `permissionDecision` 合法值：`allow` / `deny` / `ask` / `defer`。
2. **🟡 環境無 `jq`，有 python3 3.12.3**。hook 腳本**不能依賴 jq**，須改用 python3（或純 shell）解析 stdin JSON。tasks §8 C4「用 jq 或純 shell」應改為「用 python3」。

### §1.3 PreToolUse stdin 欄位（確認 C4 可行）

官方文件：所有 hook 收 base 物件 `session_id / transcript_path / cwd / permission_mode / hook_event_name / effort`；PreToolUse 另含 `tool_name` 與 `tool_input`（含 `tool_input.file_path` / `tool_input.content`）。§5 T1–T3 已實測 python 讀取 `tool_input.file_path`/`content` 成功 → C4 範圍過濾與截斷比對可行。
