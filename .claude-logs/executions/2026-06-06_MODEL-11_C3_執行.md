## §4 真因與修法

### §4.1 真因
C2 把 `embed_documents` 改為 token-aware 真批次（消費 C1 常數）。需單元測試**鎖住換用 -001 後的契約**：真批次一次回 N（不再必退逐筆）、超量自動拆批保序、task_type 非對稱、真錯誤仍退逐筆兜底——防未來重構回歸。

### §4.2 修法（`tests/test_embedding_retry.py` 唯一改檔，純測試）

1. **既有對齊**（L35，inline marker）：
   ```python
   instance.model = "gemini-embedding-001"  # === [MODEL-11 C3] 對齊換用模型（文字真批次 + task_type）===
   ```

2. **追加 4 測試**（`# === [MODEL-11 C3 START/END] ===` 包裹，全 mock `client.models.embed_content`、不打真 API）：
   - **`test_embed_documents_real_batch_no_fallback`**：mock 回等長 N 向量 → `embed_documents(["doc1","doc2"])` 回 2 normalized；`_embed_one` spy **0 呼叫**（無降級）；`embed_content` 僅 1 次（兩筆一批）；保序。
   - **`test_embed_documents_auto_split_preserves_order`**：`monkeypatch.setattr(config, "EMBEDDING_BATCH_MAX_ITEMS", 2)`〔關鍵：config.py 以 `from settings import` 綁模組級名，須 patch **config** 命名空間而非 settings〕→ `["a","b","c","d"]` 拆 `[a,b]/[c,d]` 兩批（`embed_content` 2 次）、4 向量保序合併。
   - **`test_task_type_document_vs_query`**：攔截 `embed_content` 的 `config.task_type` → `embed_documents` 全為 `RETRIEVAL_DOCUMENT`、`embed_query` 為 `RETRIEVAL_QUERY`（str 包含比對、抗 enum 強制）。
   - **`test_embed_batch_429_falls_back_to_one`**：`patch.object(instance, "_embed_batch", side_effect=Exception("429 RESOURCE_EXHAUSTED"))` + `_embed_one` spy → 退逐筆 2 次、結果長度 2 保序（驗真 fallback 不減）。

> **設計要點**：test 2 的 `EMBEDDING_BATCH_MAX_ITEMS` 必須 patch `config` 模組屬性（非 `settings`）——因 `config.py` 啟動時 `from settings import EMBEDDING_BATCH_MAX_ITEMS` 已將值 bind 進 config 命名空間，`embed_documents` 引用的是 config 全域名。已於測試註解標明此陷阱。
