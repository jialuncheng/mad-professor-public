## 真因

baron 觀察 Commit 5（多檔上傳 `b277d87`）設計錯誤：
- 多檔上傳後 confirm modal 依序跳出，但每份都要手動選 doc_type → 順序不直觀（不知道現在處理的是哪一份）
- 上傳 button 跑批次期間 disabled、體驗反而比單檔差

正確流程：
- 一次只能一份
- 點上傳 → 選檔 → 選 doc_type → 開始跑
- 想上傳第二份就再點一次上傳
- 選多份時彈出錯誤提示

## 修法

### 1. `static/index.html` — file input + handler 回退（L2401-2443）

- 移除 `input.multiple = true`
- 移除 Commit 5 加的 for-loop + `await new Promise(resolve => showConfirmModal(..., resolve))` queue 機制
- handler 改回單檔結構：
  - `files.length === 0` → return（使用者取消選檔）
  - **`files.length > 1` → `alert('一次只能上傳一份文件')` + return**（不開 modal、不 upload）
  - `files.length === 1` → 走原單檔流程（upload → showConfirmModal）
- 失敗 alert 回到「上傳失敗：{message}」單一檔錯誤訊息（不再帶檔名）
- `btn.disabled` / `setBusy` 行為回到單檔版：失敗時主動 unlock；成功則交由各檔 `trackProgress` 完成時自行 unlock

### 2. `static/index.html` — `showConfirmModal` 簽名回退（L2523, L2560-2562）

- 簽名移除第 5 參數 `onConfirmed`
- 移除 `finally { if (typeof onConfirmed === 'function') onConfirmed() }`
- 既有 dropdown / state / submit 核心邏輯：未動

### 3. `static/index.html` — Help modal 文案（L1067-1070）

- 移除第 6 條 `<li>可同時上傳多份文件</li>`
- 在 `<ol>` 之後、`step-note` 之前加一行 `<p class="step-note">每次只能上傳一份文件；如選多份會出現提示</p>`

### 4. `design/docs/copywriting.md` §6.1.1

- 標題說明改「Phase 4.7d Commit 10：一次只能上傳一份文件」
- 步驟列表回退為 5 步 + 單檔限制提示
- 互動契約改為：「file input 不設 `multiple`；若 OS 檔選擇器仍允許多選，handler 偵測 `files.length > 1` 時 alert + return、不開 confirm modal、不發 upload」
