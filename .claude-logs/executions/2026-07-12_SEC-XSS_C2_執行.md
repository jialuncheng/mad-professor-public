## §4 修改說明

### (a) `renderMarkdownWithMath` 改動前後（L324-331）

**前**：
```js
    // 6. marked.parse（math PUA 佔位穿透）
    let html = marked.parse(t);
    // 7. 回填 math：…
```
**後**：
```js
    // 6. marked.parse（math PUA 佔位穿透）
    let html = marked.parse(t);
    // === [SEC-XSS C2] === 6.5 輸出消毒：marked 產出 HTML 經 DOMPurify 過濾（防 stored XSS、
    // 一處覆蓋全部 6 個 markdown innerHTML sink）。置於 KaTeX 回填「前」：
    // PUA 哨兵（MO/MC）為純文字節點、sanitize 原樣保留 → 步驟 7 回填正則照常；
    // KaTeX 為可信產出、於消毒後插入不被過濾（含 MathML/樣式標籤）。
    html = DOMPurify.sanitize(html);
    // 7. 回填 math：…（一字不改）
```

### (b) PUA 佔位安全保留原因（管線鐵律論證）
- math 佔位哨兵 `MO`/`MC` 為 **Unicode PUA 字元 + 數字**、在 HTML 中是**純文字節點**——DOMPurify 消毒對象是元素/屬性（標籤白名單、on* 事件、javascript: URI 等），**文字節點內容原樣保留** → 步驟 7 的回填正則（`MO(\d+)MC`）照常命中。
- 消毒置於 KaTeX **前**的理由：KaTeX 產出（含 MathML/`<annotation>` 等非常規標籤）為**可信本地渲染**、若過 sanitizer 會被剝——故先消毒（不可信的 marked 產出）、後回填（可信的 katex 產出）。
- **步驟 1-5（code/ESC/img 佔位抽取）與步驟 7（回填）一字不改**——diff 對帳：本函數僅 +5 行（4 註解 + 1 消毒）、零刪零改（§5 貼證）。

### (c) 守衛測試 +1（`test_render_markdown_sanitizes_between_marked_and_katex`）
切函數體（`function renderMarkdownWithMath` → `makeThrottledRenderer`）→ 斷言三錨點順序：`let html = marked.parse(t)` < `html = DOMPurify.sanitize(html)` < `return katex.renderToString(`。
**執行期修正一次**：初版用 `katex.renderToString` 裸串——首命中落在**函數頂部鐵律註解**（佔位符文檔提及）→ 改以 `return ` 前綴鎖定**真呼叫點**（TDD 紅→綠、非湊測試）。
