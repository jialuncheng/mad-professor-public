## 真因

對應 plan §3.1：

- **marked.js 9.1.6 預設啟用 GFM `strikethrough`**（`marked.use` / `marked.setOptions` 整份 worktree 0 處自訂、跑全預設）
- **GFM strikethrough tokenizer 規則** `~+([^~\n]+?)~+` 允許**單一 `~` 配對**（不只 `~~text~~`）
- **江元杰履歷** `100~500人 ... 2003/8~仍在職` 兩個單 `~` 在同段配對為 `<del>`
- 影響面：所有 marked.parse 呼叫（paper-content + chat 共 6 處）

baron 提供圖證：
- 江元杰履歷渲染後「`500人）- 機電整合研發副理 (2003/8`」整段被劃線
- HVDC slides 內單 `~` 沒撞線（單獨一個 `~` 不配對、與本 fix 一致）

---

## 修法

對應 plan §4.1 修法 A（推薦）：

### `static/index.html` — marked.js 全域 override `del` tokenizer

位置：第一個 `<script>` block 入口（L1241 之後 / L2178 第一個 `marked.parse()` 之前）。

```javascript
marked.use({
  extensions: [{
    name: 'del',
    level: 'inline',
    start() { return -1; },        // 從不主動匹配
    tokenizer() { return false; }, // 永不產生 del token
    renderer() { return ''; }
  }]
});
```

設計重點：
- 全域 override：所有 marked.parse 呼叫（6 處）都受影響
- `start() = -1`：marked.js 不會優先掃描 del token
- `tokenizer() = false`：即使 marked 嘗試匹配也永不生成 del token
- `renderer() = ''`：兜底（理論上不會到達、但保險）
- 不關閉 `gfm: true` 整體（保留 table / autolink / breaks 等其他 GFM 特性）
