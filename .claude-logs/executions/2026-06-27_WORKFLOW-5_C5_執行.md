## §4 修法說明

### §4.1 `dirty_reset_guard.sh`（SessionEnd · Observable Fault Only）
- **機制（C1 裁定·路徑 B）**：SessionEnd 不能 block → 偵測到 dirty 即 `sys.stderr.write(...) + sys.exit(0)`，**不輸出 `decision:block`**；訊息明文標註「SessionEnd 無法阻擋結束，本訊息僅為可觀測警告」。
- **觸發條件（非「baton 非空」，避免跨 session 中途結束誤報）**：
  1. 掃 `baton/*.md`（排除 `README.md`）；無檔即 `exit 0`。
  2. 由檔名 `<YYYY-MM-DD>_<TASKCODE>_...` 取**任務代號**（`split("_")[1]`）。
  3. 解析 `TODO.md`：找該代號之 **active 區塊**（`- ... **<code>**` 起、後續 `  ` 縮排行止），若區塊內有 **Checkout 子項標 `[x]`／✅** → 判定「已 Checkout 卻未歸檔」= dirty。
  4. 任務 WIP（Checkout 未 ✅）、baton 空、代號不在 TODO → **一律不警告**。
- **解析（C1 修正·無 jq）**：純 `python3`（`open`/`glob`/字串比對），不呼叫 jq。
- **Fail-open**：`try/except Exception → exit 0`；專案根優先 `$CLAUDE_PROJECT_DIR`、否則由腳本位置 `../../` 推得。
- **威脅模型誠實（plan §1）**：本守衛為三道防線中**最弱一道**——僅可觀測、不能預防 dirty-reset（受限於 SessionEnd 能力）。

### §4.2 `test_hook_guards.sh` `dirty_reset` 子命令
- python3 建臨時 root（`.claude-logs/baton` + `TODO.md` fixture）、以 `CLAUDE_PROJECT_DIR` 注入、subprocess 呼叫守衛、斷言 stderr 是否含 `[DIRTY-RESET]`。
- 4 案例：**D1** Checkout✅+baton 有檔→警告／**D2** WIP+baton 有檔→不警告／**D3** 僅 README→不警告／**D4** 未知代號→不警告。
