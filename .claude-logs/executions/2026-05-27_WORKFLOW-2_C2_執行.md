## §4 修法說明

### §4.1 維度四：提示詞歸檔稽核

在 Conformance 驗收維度表格「不可動清單」行之後，追加：

```markdown
| **提示詞歸檔稽核** | `.claude-logs/prompts/` 物理目錄 | 執行 `ls .claude-logs/prompts/ | grep "<任務編碼>"`，確認 plan / tasks / run(s) / check 各階段 .md 實體存在；若缺失則立即補建自癒後繼續 |
```

**設計意圖**：歷史上 WORKFLOW-1 等任務的 check 階段無法確認提示詞是否實際寫入磁碟，僅靠 AI 主觀確認。維度四強制 grep 物理目錄，若缺失不得繼續收官，必須先補建。

### §4.2 維度五：msg.txt 草稿完整性

追加第五行：

```markdown
| **msg.txt 草稿完整性** | 本任務各執行報告 §8 | 確認每份執行報告 §8 含完整 msg.txt 草稿展示（含 `cat > /tmp/...` 寫入指令 + 草稿全文）；缺失則列出清單要求補完 |
```

**設計意圖**：過去執行報告 §8 有時僅有 `git add` 清單，缺少完整 msg.txt 草稿，baron 無法直接複製執行。維度五確保每份報告都有完整可執行的 commit 指令。

### §4.3 自癒例外處理條款

在「若有任何不符項」段落下方追加：

```markdown
> **若維度四（提示詞歸檔稽核）缺失**：Claude Code 必須立即補建缺失提示詞 .md 物理檔案，補完後繼續收官；**若維度五（msg.txt 草稿完整性）不合規**：列出缺失 §8 msg.txt 展示的執行報告，要求 baron 確認後收官。
```

**設計意圖**：維度四可自動修復（補建文件），維度五需人工確認（可能是有意略簡），因此分兩種處理路徑。
