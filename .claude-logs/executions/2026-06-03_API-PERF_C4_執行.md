## §4 修法說明（含架構備註）

### §4.1 U1 並發信號量（`settings.py` + `web_server.py`）
- `settings.PIPELINE_MAX_CONCURRENT=1`（env override）。
- 模組級 `PIPELINE_SEMAPHORE = asyncio.Semaphore(settings.PIPELINE_MAX_CONCURRENT)`。
- **A 軌 `run_pipeline`**：派發前若 `PIPELINE_SEMAPHORE.locked()` → 設 `status='queued'` + progress `{stage:'queue', stage_name:'等待佇列中...（排隊中）'}`；`async with PIPELINE_SEMAPHORE:` 取得許可後設 `'processing'` 並 `run_in_executor(pipeline.process(...))`。**`pipeline.process(...)` 調用內容/參數不動**（僅縮排一層至 `async with` 內，spec 允許之「外層包裝」）。
- **B 軌 `run_pipeline_shadow`**：同構守護 `Orchestrator().run(ctx)`，與 A 軌共用同一信號量（全系統並發上限統一，PIPE §2 U11 QUEUE-1 廢除底座）。
- SSE `paper_status` 既有迴圈自然推 `queued`（未改 SSE 結構）。

```python
if PIPELINE_SEMAPHORE.locked():
    with tasks_lock:
        processing_tasks[task_key]['status'] = 'queued'
        processing_tasks[task_key]['progress'] = {'stage':'queue','stage_name':'等待佇列中...（排隊中）',...}
async with PIPELINE_SEMAPHORE:
    with tasks_lock: processing_tasks[task_key]['status'] = 'processing'
    pipeline = PipelineCore(on_progress=on_progress)
    output_paths2 = await loop.run_in_executor(None, lambda: pipeline.process(...))  # 本體不動
```

### §4.2 U2 子進程 nice（`processor/pdf_processor.py`）
`_lower_subprocess_priority()`（`os.nice(19)` + `except (AttributeError, OSError)` soft-fail）+ `_NICE_PREEXEC = _lower_subprocess_priority if hasattr(os,'nice') else None`；兩處 `subprocess.run`（ssh 取目錄 / scp 取圖）加 `preexec_fn=_NICE_PREEXEC`。
- **架構備註（誠實揭露）**：本專案 MinerU 轉檔為**遠端 HTTP 服務**（`MINERU_API_URL`），`pdf_processor` 的本地 subprocess 僅 `ssh`/`scp`（網路 I/O、非 CPU 大宗）。故 nice 對「降低本地 CPU 佔用」於現行架構效益有限；本 Commit 依 tasks §8 C4 規格於 `pdf_processor` 子進程落地 nice 基礎建設（preexec_fn + Windows soft-fail），供未來若引入本地 CPU 解析子進程時即生效。重 CPU 的本地工作實際在 `run_pipeline` 的 `run_in_executor` 執行緒（受 U1 信號量限流），非子進程。

### §4.3 `tests` — C4 測試（2 項）
`test_concurrency_semaphore_queue`（佔用信號量 → 第二任務 `queued`；釋放 → 自動啟動並 `done`）/ `test_subprocess_nice_soft_fail`（`_lower_subprocess_priority` 可呼叫不拋；`_NICE_PREEXEC` 為 None 或 callable）。
