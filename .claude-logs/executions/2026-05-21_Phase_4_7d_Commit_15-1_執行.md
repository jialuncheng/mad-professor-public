## 修法

### A. 跳過空 summary chunk（`_generate_md_content` L332-340）

**改前**：
```python
if "summary" in node and "/section" in key:
    md_content += f"{node.get('summary', '')}"
    return md_content   # 空字串也返回、產生空殼 chunk
```

**改後**：
```python
if "summary" in node and "/section" in key:
    summary = (node.get('summary') or '').strip()
    if not summary:
        return None   # _generate_markdown L318 已有 if md_content: 護欄
    md_content += summary
    return md_content
```

### B. chunk 內容前綴加 Context 標籤

`_generate_md_content` 簽名加 2 個 optional 參數：
```python
def _generate_md_content(self, node, key,
                         doc_type: str = '', section_title: str = '') -> str:
    md_content = f"# {key}\n"
    ctx_bits = [b for b in (doc_type, section_title) if b]
    if ctx_bits:
        md_content += f"Context: {' > '.join(ctx_bits)}\n\n"
    # 既有 type 分支不動
```

caller 端 `_generate_markdown` 傳 `doc_type` + `_extract_section_title(key)`。

**範例輸出（resume）**：
```
# DeHunt Resume/Working Experience/VIEWTRIX/section/0/text
Context: resume > Working Experience > VIEWTRIX

職位：資深 IC 設計工程師
2018-2022
...
```

預設空字串 → 行為等效既有（向下相容）。

### C. 新 helper `_extract_section_title(key)`

從 key 路徑萃取 section title、去 paper_title 前綴 + `/section/...` 尾段：

| input key | output |
|---|---|
| `DeHunt Resume/Working Experience/section` | `Working Experience` |
| `DeHunt Resume/Working Experience/section/0/text` | `Working Experience` |
| `DeHunt Resume/Working Experience/VIEWTRIX/section` | `Working Experience > VIEWTRIX` |
| `''` / 單 segment | `''` |

`_LEAF_MARKERS = ('section', 'text', 'figure', 'table', 'formula')` 為截斷邊界。

### D. 短文 doc_type 合併同 section text items

新增 module-level：
```python
# === doc_type-registry ===
_SHORT_DOC_TYPES = frozenset({'resume', 'slides', 'news', 'web'})
```

新 helper `_try_merge_text_items(section, tree, doc_type, sec_idx, ch_idx=None)`：
- text_items < 2 → 返回 None（不必合併）
- 全空 → 返回 None
- 否則合併為單一 chunk、key 加 `/_merged` 後綴避免衝突
- 含 Context 前綴

新 helper `_item_key(...)`：重建 per-item key、與 `_generate_key_map` 對齊；merge 後標記跳過原 per-item 處理。

`_generate_markdown` 主流程：
1. `is_short_doc = doc_type in _SHORT_DOC_TYPES`
2. 若 is_short_doc → 先掃 sections（含 1 級 children）、寫 merged chunks、收集 `merged_skip_keys`
3. 再跑既有 key_map 遍歷、跳過 `merged_skip_keys`、其他 chunks 走原路徑（含 Context 前綴）

### E. `pipeline_core._stage_rag` 傳 doc_type

doc_type = output_paths.get('_confirmed_doc_type', 'academic')
