## §4 修法說明（§99.1 三維度定義）

於 §99.1 治理規格表（「重複防護」列之後）新增三列，並於表後追加兩條註：

1. **Scope（範疇）**：作用域宣告 `session-private`（單 session 暫存、不跨會話）或 `project-shared`（跨會話／跨工具共享真理源），預設 `project-shared`。→ 供 baton README §2 **Phase 2 Scope 自檢**與歸檔目錄判定。

2. **Provenance（溯源）**：來源出處＝產生來源（plan／tasks／baron 指令／上游真理源）＋ 來源 commit hash 或 session。→ 供 baton **Phase 2 Provenance 自檢**與 Audit Trail 回溯。

3. **Fidelity Floor（降級底線）**：Token 緊張時多解析度降級之**下限——降到此層即不得再降**。
   - **機器可讀格式（供 hook 解析）**：`fidelity_floor: <Full|Structured|Pointer>`；可逐類細列如 `Constraint=Structured; 不可動清單=Structured; Evidence=Pointer`（`key=Level` 分號分隔之可解析格式）。
   - **四 Level 殘留鏈**（由高至低）：`Full → Compressed → Structured → Pointer`（對齊 ClawVM Table 1 多解析度）。
   - **為 C4 Floor 守衛預留**：C4 第二階段 Floor 守衛可解析此欄判定「寫入是否使既有檔跌破其 floor」。

**Cost-Aware 保留原則**（表後註）：標 `no-degrade` 之 evidence（grep 證據／實測輸出／commit hash 等重算昂貴者）於降級時**優先保留**、不隨一般內容降級。

**邊界**：僅改 §99.1 表 + 表後兩註 + §99.2；§0／§1 模板骨架未動。
