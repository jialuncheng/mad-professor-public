## §4 修法說明

### §4.1 `pre_tool_guard.sh`（PreToolUse 截斷守衛）
- **入口**：`exec python3 -c '<inline>'`——bash 不解析 JSON，直接交 python3 讀 `sys.stdin`（hook 傳入的 PreToolUse JSON）。**繞過 heredoc/stdin 衝突**（python 腳本走 `-c` argv、JSON 走 stdin）。
- **解析（C1 修正·無 jq）**：`json.load(sys.stdin)` 取 `tool_name`、`tool_input.file_path`、`content`/`old_string`/`new_string`。
- **範圍過濾**：`file_path` 命中保護集 `("CLAUDE.md","TODO.md","/plans/","/sop/","/ref/")` 才檢查；其餘 + 非 Write/Edit 一律放行。
- **截斷判定（>50% 且 >50 行）**：
  - `Write`：現檔行數 `cur_lines` vs 新 `content` 行數；`shrink = cur-new`，`shrink > 50 且 shrink > 0.5*cur` → deny。
  - `Edit`：`removed = old_string 換行數 − new_string 換行數`，`removed > 50 且 removed > 0.5*cur` → deny。
  - **新檔（on-disk 不存在）→ 無可截斷 → 放行**。
- **攔截機制（C1 修正·非 exit 2）**：`deny()` 輸出 `exit 0` + stdout
  `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"...提示加 // BYPASS_TRUNCATION_GUARD 放行..."}}`。
  > 採官方文件權威欄位 `hookEventName` + `permissionDecisionReason`（較提示詞精簡寫法 `reason` 更完整對齊 C1 取得之文件規格）。
- **Bypass 減速帶（plan §1 Threat Model）**：寫入內容含 `// BYPASS_TRUNCATION_GUARD` → 放行。腳本註解誠實標明此守衛**防誤觸、agent 可繞過**，不可繞過保證僅在 baton 3-Phase。
- **Fail-open**：`try/except Exception → sys.exit(0)`（無 JSON）。hook 絕不因自身錯誤把人鎖在外。
- **Floor 守衛（第二階段）**：本 commit **不實作**；待消費 C3 `fidelity_floor:` 機器可讀格式後另議（tasks §4.4 預留）。

### §4.2 `test_hook_guards.sh`（乾跑/單元測試）
- `truncation` 子命令以 python3 建 fixture（200 行保護檔）+ 組 JSON + `subprocess` 呼叫守衛 + 斷言；`dirty_reset` 子命令為 C5 佔位。
