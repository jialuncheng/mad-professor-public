## §5 修法

### 5.1 `tools/regen_rag.py` 替換 main 入口 logging 初始化

grep 證實既有 `logging.basicConfig` 唯一位置在 `__main__` block（L344-347）：

**改動前**：
```python
if __name__ == '__main__':
    logging.basicConfig(
        level=logging.INFO,
        format='%(asctime)s %(levelname)s %(message)s',
    )
    main()
```

**改動後**：
```python
if __name__ == '__main__':
    # LOGGING-3：CLI 統一用 setup_logging（取代 logging.basicConfig 寫死）
    # 依 .claude-logs/2026-05-23_logging_refactor_可行性評估.md v4 §6 LOGGING-3 行
    # 受 settings.py LOG_LEVEL / LOG_DIR / LOG_FORMAT env 控制、跟 web_server 共用一套配置
    # 沿用 LOGGING-1 補強 1 冪等性 guard、多次呼叫零風險
    from utils.logging_config import setup_logging
    setup_logging()
    main()
```

**關鍵設計**：
- 把 `from utils.logging_config import setup_logging` 放在 `__main__` block 內（不放在檔頂全域 import）：避免從別處 `import tools.regen_rag` 時自動觸發 setup_logging、相容 pytest 收集階段
- `import logging` 保留（cmd_regen / cmd_init 內 `logging.getLogger(...)` 仍需）
- 其他 import / 函式 / cmd_check / cmd_regen / cmd_all / cmd_init / main / argparse 100% 不動

### 5.2 `tests/test_regen_rag_cli.py` 補 1 個 pytest

新 case：`test_main_uses_setup_logging_not_basic_config`

| 驗證項 | 檢查方式 |
|---|---|
| source 內無 `logging.basicConfig(` 實際呼叫 | regex `^\s*logging\.basicConfig\s*\(` 匹配（容許註解內提及） |
| `setup_logging` 已 import | `from utils.logging_config import setup_logging` 字串存在 |
| 冪等性：多次 `setup_logging()` 不掛重複 handler | `reset_logging()` → `setup_logging()` → 記 N1；再 `setup_logging()` → N2；assert N1 == N2 |
| 後續 test 復原 | `reset_logging()` 收尾 |

**規避陷阱**：第一次寫 `assert "logging.basicConfig" not in src` 失敗——因為新代碼註解內提及該字串；改用 regex 只匹配實際呼叫（行首縮排 + `logging.basicConfig(`）。
