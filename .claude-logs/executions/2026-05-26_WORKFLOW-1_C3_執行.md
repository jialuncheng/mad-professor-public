## §4 修法說明

### §4.1 `template_prompt_for_plan.md` — 規劃提示詞模板

依 plan §1.10.7 規格，最小必含：
- **任務編碼 + 任務簡述**：`<任務編碼>` / `<任務簡述>` 佔位符
- **強制讀檔清單**：CLAUDE.md（自動載入）+ WORKFLOW_SOP.md + 框架 + BE 工作流時的 logging/database SOP
- **撰寫原則**：純規格、What it should be（無 Why）、證據驅動（grep + 行號）、Open Questions 三欄
- **套用 template_plan.md 結構**：九章節表格（TL;DR / 目標規格 / 現況與證據 / 不可動清單 / 規格依據 / 驗證計畫 / Open Questions / §99）
- **產出路徑規格**：`.claude-logs/plans/<YYYY-MM-DD>_<任務編碼>_<描述>_plan.md`
- **明確停止指令**：產出 plan.md 即停，嚴禁拆 commit 或動業務代碼

### §4.2 `template_prompt_for_tasks.md` — 任務拆分提示詞模板

依 plan §1.10.8 規格，最小必含：
- **任務編碼 + 工作流類別**
- **強制讀檔清單**：CLAUDE.md + WORKFLOW_SOP + plan.md + TODO.md + template_tasks.md
- **工作目錄硬規則提醒**：唯一合法目錄 + 嚴禁主 repo + 嚴禁業務代碼
- **§0.5 成果盤點約束**：強置文件開頭，含新/改/目錄/狀態/Commits 五欄表格範本
- **彈性 commit 規劃約束**：可依最佳施行方式彈性安排
- **§8 六維度表格要求**：影響範圍 / 安全性 / 可逆性 / 驗收 grep 條件 / 依賴關係 / 具體實作細節
- **§1 TL;DR 中文括號命名要求**：`C1 — Bootstrap Core（自動載入核心）` 格式範例
- **同步更新 TODO.md**：新增任務條目 + 設 🟡 WIP
- **歸檔 baton plan**：`mv + git add` 指令範本
- **明確停止指令**：產 tasks.md 與更新 TODO.md 後即停

### §4.3 `template_prompt_for_run.md` — 原子執行提示詞模板

依 plan §1.10.9 規格，最小必含：
- **元數據審計塊**：收到時間 / 任務代號 / 觸發 commit / 相關產出檔案 / 觸發情境（五欄表格）
- **單一 Commit 代號指定**：`<Commit代號>` 佔位符，強調每次只執行一個
- **工作流類別 + 強制讀檔清單**
- **三個防線**：物理防線（§7 不可動清單）/ 測試防線（§6 測試計畫）/ 文件防線（嚴禁自發 commit）
- **備份規則**：修改前先備份至 `archive/`
- **§8 baron 手動執行命令格式要求**：git add 清單 + `/tmp/<任務編碼>_<Commit代號>_msg.txt` + `git commit -F` 指令
- **明確停止指令**：產出 `_執行.md` 後即停，嚴禁繼續執行下一 Commit

### §4.4 `template_prompt_for_sop.md` — SOP 撰寫提示詞模板

依 plan §1.10.10 規格，最小必含：
- **SOP 領域名稱**：`<領域名稱>` 佔位符
- **強制讀檔清單**：WORKFLOW_SOP.md §5 SOP 核查 + 既有相關 SOP + codebase grep
- **撰寫原則**：規範性 / 可 grep 化 / 含核查指令（每條「必須」/「嚴禁」後附 grep 驗證）

- **產出規格路徑**：`.claude-logs/sop/<YYYY-MM-DD>_<領域>_SOP_手冊.md`（≤ 150 行）
- **明確停止指令**：產 SOP 手冊即停

### §4.5 `template_prompt_for_check.md` — 檢驗與收官提示詞模板

依 plan §1.10.11 規格，最小必含：
- **任務編碼 + plan + tasks + 執行報告清單**：全量路徑佔位符
- **強制讀檔清單**：CLAUDE.md + plan + tasks + 所有 _執行.md + TODO.md
- **Conformance 驗收流程**：三維度（目標規格 / 測試計畫 / 不可動清單）+ 驗收報告表格格式
- **不符項處理**：明確列出例外、拒絕收官、等 baron 拍板
- **收官自動化動作（全部合規後）**：
  1. 更新 TODO.md（WIP → 完成，加 hash 表格）
  2. 歸檔 baton/ 暫存文件（`mv + git add` 各類別指令）
  3. 確認 baton/ 只剩 README.md

- **明確停止指令**：完成歸檔後即停，嚴禁自發 git commit
