## §4 修法說明

### §4.1 `processor/pdf_processor.py` — CPU 鎖定 comment

在 `data` dict 中 `"backend": "pipeline"` 上方插入 2 行說明性 comment：

```python
data={
    "return_md": "true",
    "response_format_zip": "true",
    # CPU 環境必須鎖定 pipeline backend（PaddleOCR + RapidTable）
    # hybrid_auto（MinerU 預設）在無 GPU 時永久卡死 Predict: 0%
    "backend": "pipeline",
    # MinerU 3.1.6 預設 return_images=False，不設則 ZIP 無圖
    "return_images": "true",
},
```

**設計理由**：comment 說明 CPU 鎖定根因，配合 Case D 測試形成雙重防護，防止未來重構時誤刪或改成 `hybrid_auto`。

### §4.2 `tests/test_pdf_processor_timeout.py` — Case D 新增

在 `TestMineruTimeout` class 末尾追加 `test_backend_parameter_is_pipeline`：
- Mock `requests.post`，呼叫 `proc.process()`
- 斷言 `call_kwargs.get("data", {}).get("backend") == "pipeline"`
- 錯誤訊息明確說明 CPU 卡死後果

### §4.3 `.env.example` — VRAM CPU 禁用警告

在 `MINERU_TIMEOUT=1800` 後插入：
```bash
# ⚠️  CPU 部署模式下，嚴禁設定 MINERU_VIRTUAL_VRAM_SIZE：
#     設為 8 → 程式嘗試分配 8GB 虛擬 VRAM，導致容器 OOM 崩潰
#     設為 4 → 拖慢 MinerU 推理約 33 秒（CPU 排程頻繁喚起 GPU 路徑）
#     GPU 容器中才設定此變數；CPU 部署一律保持此行被完整移除（不留空值也不留 key）。
```
