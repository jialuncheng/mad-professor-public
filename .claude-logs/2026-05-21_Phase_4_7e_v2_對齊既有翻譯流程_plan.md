> 基準：7e-1 (`ffb3000`) + 7e-2 (`fdc2838`) 已 revert（`ce91665` / `32563b5`）
> 樣本：6 份履歷已含 `final_*_en.md` / `final_*_zh.md` 既有 pipeline 跑過的成品（在 `/tmp/phase_4_7e_samples/resume_samples/{paper}/`）

## TL;DR

實看 6 份履歷的 `final_*_en.md` / `final_*_zh.md` 後**重大發現**：

> **既有 pipeline 已經完美做到「翻譯保留排版」**——當 MinerU 輸入 markdown 結構正確時，整條 academic 路徑（pdf2md → md_cleaner → doc_analyzer → md_processor → tiling → translate → md_restore）逐句中譯保留 heading / table / list / image 排版毫無問題。

7e-1 Vision prompt 走偏了——它做「重組 + 摘要」（重寫主標題、合併 Edu/Skills 進 prose、跨履歷彙整 Technical Skills），與本專案「忠實轉錄 + 翻譯保留排版」哲學完全相反。

### 新方向：ResumeProcessor 只做「忠實轉錄 + 補抽漏掉的 ###」

- ✅ 用 Vision 看 PDF 全文（純圖檔 / OCR 失敗也救得回）
- ✅ 補抽 plain text 公司 / 學位為 ###（MinerU 漏掉的唯一加工）
- ✅ 保留所有 section 名稱（Working Experience / Skills / Recommendations / Honors）
- ✅ 保留條列 / 段落 / **markdown table** / image 連結
- ❌ 不重組主標題（保留人名原樣 #）
- ❌ 不整合 Edu/Skills 進「Candidate Summary」
- ❌ 不彙整跨履歷「Technical Skills」
- ❌ 不翻譯（後續 translate stage 處理）
- ❌ 不摘要（後續 extra_info stage 處理、且 resume 在 `_SHORT_DOC_TYPES` 走 `generate_document_summary`）

## 1. 既有「翻譯保留排版」流程完整盤點

### 1.1 Stage 對照表

| Stage | 對 markdown 操作 | 影響排版 | 對 resume 適用度 |
|---|---|---|---|
| `pdf2md` (MinerU) | OCR + 抽 heading + table + image | 原文結構抽取 | ⚠ 對 resume 部分 heading 抽不到（FOCALTECH/NOVATEK） |
| `md_cleaner` | 清純數字行 + 7a 浮水印 heading | 清雜訊、不動結構 | ✅ 對 resume 浮水印有用（DeHunt XDeHunt） |
| `analyze` (doc_analyzer) | LLM 修 # 數量 + 寫 `_doc_structure.json` sidecar | 修正 heading 層級 | ⚠ resume 重用 academic prompt（7b 已專屬化但仍不夠） |
| `md2json` (md_processor) | markdown → 結構化 JSON sections tree | 切 section、不改文字內容 | ✅ 適用 |
| **`tiling`** | sections 內 content 按 embedding 相似度切 chunk（min 500 / max 2500 字）| **不改 markdown、只切 JSON chunk 邊界**| ✅ 適用 |
| **`translate`** | JSON 內每 chunk 中譯、寫到 `translated_content` 欄位；中文用繁體台灣語境，**保留換行 / 公式 / 序號**、姓名不譯、地名 / 機構 + 原文 | **不動 markdown 結構**——只在 JSON 加翻譯欄位 | ✅ 適用 |
| `image_caption` | Vision 看 images/*.jpg 生 `images_info.md` | 不動 markdown | ✅ 適用 |
| **`md_restore`** | JSON 重組成 `final_*_en.md`（原文）+ `final_*_zh.md`（中譯）；保留 heading / table / image / list | **這裡才寫最終 markdown**！ | ✅ 適用 |
| `extra_info` | 抽 question / summary（給 chat 用）| 不動 markdown | ✅ resume 在 `_SHORT_DOC_TYPES` 走 summary-only |
| `rag` | sections → embedding chunks（給 retrieval）| 不動 markdown | ✅ resume 在 `_SHORT_DOC_TYPES` 走短文合併 |

### 1.2 關鍵發現：「翻譯保留排版」的真正 owner

`processor/md_restore_processor.py::_process_section()`（L572）+ `process()`（L742）。

- 讀 `tiled.json`（含原文 + translated_content）+ `images_info.md` + metadata
- 為每個 section 寫 `final_{paper}_en.md`（原文 + 圖片 + 圖說）+ `final_{paper}_zh.md`（中譯 + 圖片 + 中譯圖說）
- **完全沿用原 heading_level**（## / ### / ####）、原 table、原 list、原 image link `![](images/...)` 

**結論：「翻譯保留排版」由 md_restore 統一負責**——任何 doc_type 只要 .md 結構正確、json 翻譯欄位齊全，md_restore 自然產出對齊的 en/zh 雙版本。

### 1.3 翻譯規則（`prompt/translate/content_translate_prompt.txt` 摘錄）

```
你是專業學術論文與書籍翻譯助手...翻譯為繁體中文。
請保留原文的換行符、公式、序號等，不要增加新的換行符...
姓名不要翻譯
地名翻譯後要附上原文
機構名稱翻譯後要附上原文
```

→ 完全符合 baron 期望：保留排版、姓名不譯、機構 + 原文。**這 prompt 對履歷已經夠用、不需 resume 專屬版。**

## 3. resume 對齊既有架構的設計哲學

### 3.1 既有 doc_type 處理哲學

| doc_type | pdf2md | md_cleaner | 翻譯保留排版 |
|---|---|---|---|
| academic | MinerU | ✅ 跑 | ✅ md_restore 統一處理 |
| book | MinerU | ✅ 跑 | ✅ 同上 |
| technical | MinerU | ✅ 跑 | ✅ 同上 |
| news / web | MinerU | ✅ 跑 | ✅ 同上 |
| **slides** | **SlidesProcessor（Vision per-page）**| ❌ 跳過 | ✅ 同上 |

→ slides 是「Vision 取代 MinerU」的先例、但仍**走相同 translate + md_restore 鏈**、不重組摘要。

### 3.2 resume 該對齊

**只取代 pdf2md 階段、後續 stage 全部沿用**：

- 用 ResumeProcessor 取代 MinerU 抽 markdown（仿 slides）
- 輸出**忠實轉錄** PDF 全文（不刪 / 不增 / 不改寫）
- **唯一加工**：MinerU 漏抽的 plain text 公司 / 學位 → 補上 `###`
- 保留原 PDF 條列 / 段落 / **table** / image 連結
- 後續 md_cleaner / doc_analyzer / md_processor / tiling / translate / md_restore 全部維持既有 academic 邏輯

### 3.3 與 academic 的細微差異

| 面向 | academic | resume v2 |
|---|---|---|
| pdf2md | MinerU | ResumeProcessor（Vision 全頁） |
| md_cleaner | 跑（清純數字行 + 7a 浮水印） | 視情況：若 ResumeProcessor 已乾淨可跳過、否則沿用 |
| analyze 的 heading_fix | LLM 修 # 數量 | **可以保留**（ResumeProcessor 輸出仍可能有 LLM 誤判 # 數量）；或短路、看實測 |
| translate 規則 | academic prompt | **沿用** academic（履歷適用） |
| extra_info | 全跑 | resume 已在 `_SHORT_DOC_TYPES` 走 summary-only（既有設計）|
| rag | 標準 chunk | resume 在 `_SHORT_DOC_TYPES` 走短文合併（既有設計）|

## 4. ResumeProcessor 新設計（vs 7e-1 已 revert）

### 4.1 ResumeProcessor v2 該做的事

```python
class ResumeProcessor(PDFParser):
    def parse(self, pdf_path, output_dir) -> Path:
        # 1. PyMuPDF render 每頁 JPEG
        # 2. Vision LLM 整份重看、忠實轉錄全文
        #    - 保留原 PDF 所有文字（人名 / 公司 / 期間 / 職責 / 條列 / 段落）
        #    - 保留原 section 名稱（Working Experience / Skills / Recommendations / Honors / etc）
        #    - 保留原 table 結構（用 markdown table 或 HTML table、看 MinerU 慣例）
        #    - 保留 image 引用（若 PDF 有圖、Vision 認出後寫 ![](images/...) 連結）
        # 3. 唯一加工：補抽 plain text 公司 / 學位為 ### heading
        # 4. 寫 {paper_name}.md
```

### 4.2 ResumeProcessor v2 **不**該做的事（與 7e-1 對照）

| 7e-1 做的（已 revert） | v2 不該做 | 理由 |
|---|---|---|
| 重組主標題為「{職稱} Resume - {人名}」 | ❌ | 主標題保留原 PDF（人名）；md_restore 已能處理 |
| `## Candidate Summary` 整合 Edu/Skills/Honors prose | ❌ | 摘要是 extra_info / chat 對話框的功能；履歷應保留原 section（Education / Skills / Honors 各自 ##）|
| 跨履歷彙整 `## Technical Skills` 區段 | ❌ | 違反「忠實轉錄」；技能該保留在原 PDF 出現的 section（Skills / Software Tools / Honors）|
| 「以英語為主」的多語規則 | ❌ | 違反「保留原文」；中文履歷就是中文、英文就英文、中英並列就保留並列；translate stage 才負責中譯 |
| 把 list 強轉 prose | ❌ | 違反「保留排版」 |

### 4.3 與 SlidesProcessor 對齊度

| 面向 | SlidesProcessor | ResumeProcessor v2 |
|---|---|---|
| 繼承 | `PDFParser` | 同 |
| 渲染 | PyMuPDF Matrix(2.0) | Matrix(2.5)（履歷字密） |
| Vision call | per-page（每頁產 `## {頁標題}`）| **整份一次**（保結構連貫 + 補 ### 需要全局視野） |
| 輸出 | 每頁一個 `## {標題}` + image | 忠實轉錄 PDF 結構 + 補 ### |
| Vision prompt | 簡潔 / 表格 / 條列規則 | **忠實轉錄 + 補抽 ###（單一加工）** |
| 失敗模式 | warn + skip | raise PDFParseError |

## 5. 新 Vision prompt 草案（忠實轉錄型）

```
你是處理「履歷 / Curriculum Vitae / CV」的 AI 助手。請看完這份履歷的所有頁面、把 PDF 內容**忠實轉錄**成 markdown，方便後續翻譯與 RAG 檢索。

# 核心原則（嚴格遵守）

1. **忠實轉錄**：原 PDF 寫什麼就抄什麼，不增不減不改寫
   - 不要把 list 轉成 prose、不要把 prose 拆成 list
   - 不要合併 / 拆分 section（原 PDF 有什麼 section 就保留什麼）
   - 不要重組標題格式（原 PDF 第一行寫「Tzung-Yuan Lee」就 # 寫人名、不要改成「CTO Resume - Tzung-Yuan Lee」）

2. **保留原語言**：原 PDF 是英文就英文、中文就中文、中英混合就保持混合
   - 不要翻譯（後續 stage 會做）
   - 不要把中英並列改成單一語言

3. **唯一允許的加工**：補抽 plain text 公司 / 學位 / 項目為 ### heading
   - 理由：MinerU OCR 有時把公司名識別為普通段落（如 DeHunt 履歷的 FOCALTECH / NOVATEK），但人類讀者一眼看得出這是公司名
   - Vision 看到「在 Working Experience / Work Experience / 工作經歷 等 section 下面、以粗體 / 大字 / 獨立一行出現的『公司全名 + 職稱 + 期間』」應補 `### 公司名 - 職稱 (期間)`
   - 同理：Education / 學歷 下面的學校 + 學位 + 期間 也補 ###
   - **若 PDF 用 table 列出學歷 / 工作（如 YuLun_Wu 案例），保留 table 不要拆**

# 輸出格式

- 第一行 `# {原 PDF 上的主標題}`（通常是人名、不要改寫格式）
- 後續按原 PDF 順序保留所有 section（## level）：
  - 中文履歷可能是：個人資料 / 學歷 / 工作經驗 / 技能專長 / 自傳 / 求職條件 等
  - 英文履歷可能是：Summary / Education / Working Experience / Skills / Publications / Honors / Recommendations 等
  - 都保留原名稱、不統一翻譯
- Working Experience / 工作經驗 等下面、每家公司用 ### 一個區塊（補抽 plain text 公司是唯一允許的加工）
- 條列 / 段落 / table / image 全部按 PDF 原樣
- 推薦信 / 求職信內容如果出現在履歷尾頁、保留為 `## Recommendation Letters` / `## Recommendations` section（不要刪也不要併進其他 section）

# 邊界 case

- **公司是 plain text 但 PDF 上是粗體 / 大字 / 對齊獨立**：補 `###`
- **公司就是普通段落內提到（自傳裡複述）**：不補（避免重複）
- **學歷 / 工作用 table 列**：保留 table、不拆
- **多家公司是 freelance / 個人接案**：忠實轉錄、不強塞「Working Experience」結構
- **雙語履歷（同 PDF 含英文版 + 中文版並列）**：保留兩個語言版本（不擇一刪）
- **浮水印 / 公司 logo 重複文字**：不抽進輸出（這是 md_cleaner 7a 該管的、但 vision 也應自動忽略）
- **學生履歷無工作經歷**：保留 PDF 原 section（如 Education / Projects / Internship 等）、不強造 Working Experience

# 輸出限制

- 只輸出 markdown 內容、不要 introductory text（不要「以下是您的履歷整理」等）
- 從 # 主標題那行直接開始
- 不要用 ```markdown ... ``` code fence 包裹
- 不要在末尾加總結 / 註釋
```
