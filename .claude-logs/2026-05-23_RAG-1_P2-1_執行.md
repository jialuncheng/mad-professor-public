### 3.2 `pipeline_core.py::_stage_translate`

translate stage 完成後同步 `translate_processor.translated_abstract` 進 `self._metadata`：

```python
result = self.translate_processor.process(
    str(input_path), str(output_path), doc_type=doc_type, domain=domain
)
# RAG-1 Phase 2 P2-1：translate 階段完成後、把 translate_processor 內
# 已賦值的 translated_abstract 同步寫進 self._metadata，供下游 stage
# 與前端中文模式 abstract 顯示。translate_processor.translated_abstract
# 屬性確認存在（L20 init / L165 賦值 / L310-312 使用）。
try:
    translated_abstract = getattr(
        self.translate_processor, 'translated_abstract', None
    )
    if translated_abstract and isinstance(self._metadata, dict):
        from processor.metadata_extractor import _empty_field
        field = self._metadata.get("translated_abstract")
        if not isinstance(field, dict):
            field = _empty_field(is_list=False)
        field["value"] = translated_abstract
        field["source"] = "translate_pipeline"
        field["confidence"] = "high"
        self._metadata["translated_abstract"] = field
except Exception as exc:  # defensive: 任何失敗不阻塞 translate 主流程
    logger.warning(
        "[P2-1] 寫入 translated_abstract 到 _metadata 失敗: %s", exc
    )
return result
```

**設計重點**：
- **try/except 防禦**：寫入失敗不影響 translate 主流程（既有 paper 不會因為新邏輯破裂）
- **空值不覆寫**：`translated_abstract` 為 `""` / `None` 時、保留 `_empty_field` 結構、value 仍 `None`（pytest #3 驗證）
- **source / confidence 對齊 schema**：`source="translate_pipeline"`、`confidence="high"`（區隔 LLM 與 PDF metadata 來源）
- **不破壞既有 metadata**：只在 `self._metadata` 為 dict 時動作；若 stage_analyze 未跑、`_metadata` 缺 → 跳過

## 4. 真因分析（依框架 §3）

### 為什麼 translated_abstract 一直為空？

**真因**：`translate_processor.translated_abstract` 雖在 `__init__` 賦值、且 translate 主流程內也填值、但 **`pipeline_core` 從未把它寫回 `self._metadata`**——translate stage 結束後該屬性的值就只活在 `_translate_processor` 物件內、`_metadata` JSON 永遠缺 `translated_abstract` 欄位。

**Phase 1 R1 子項 F 已加前端 fallback**（中文模式 abstract 缺時 fallback 英文）、但**後端來源不補、前端永遠 fallback**——體驗對中文 user 持續破裂。

P2-1 修這條缺漏的「translate_processor → metadata JSON」寫回路徑、根治問題。

### 為什麼不直接擴 translate_processor 屬性？

P2-1 Q1 grep 顯示屬性**已存在**、且已被 translate 主流程內部當 prompt reference 使用、語義穩定。本次 +20 行擴屬性會違反 §6 不可動清單「translate_processor 內部行為不動」。
