## TL;DR

1. **三軸 = (raw markdown / metadata / domain)**，三者由 pipeline 不同階段生成、互相獨立、**可組合也可衝突**。
2. **目前融合策略：沒有**。md_restore 第 244-248 行只認 `data['title']`（raw markdown 抓的 first-#），完全忽略 metadata 與 domain。
3. **正確融合策略 = doc_type-agnostic 決策核心 + doc_type-specific header template**：
   - **核心**（共用）：title 黑名單 → 信心度比對 → fallback 鏈 → domain sanity check
   - **客製**（每 doc_type 一份）：header template（哪些欄位寫進開頭、用什麼順序、要不要跳過原 first-#）
4. **新增 doc_type 步驟現況**：
   - `docs/HOW_TO_ADD_DOC_TYPE.md` 列了 **7 個 registry marker 點**
   - 實際 doc_type 分支共有 **15 處**——8 處沒進 registry / 沒 marker / 沒 check 腳本驗證
   - Phase 4.7d 順帶把 marker 補齊
5. **PART III 既有 7 個 doc_type 逐項檢查結果**：每個 doc_type Step 1-10 中**至少有 Step 8 未做（md_restore 融合）**，這就是 Phase 4.7d 的核心工作。其餘多數 step 都已 fallback academic / 客製完備。
6. **abstract 中英翻譯**目前在 translate_processor 有實作（針對 academic/book/technical；slides/news/web 跳過），**4.7c PENDING 的修復項實際指**：md_restore 注入時要寫 translated_abstract，目前 `translate_processor.translated_abstract` 是 stateful 內部欄位、沒寫進 JSON tree——這是 4.7d 的子工作。

# PART I：三軸融合分析

## A. 三軸資料來源完整盤點

### A-1 raw markdown 軸（pdf2md → md_processor）

**產生位置**：
- `pdf2md`：MinerU API（academic/book/technical/news/web/resume）/ SlidesProcessor Vision LLM（slides）
- `analyze` heading_fix：LLM 改寫 `#/##/###` 層級
- `md2json`：`md_processor.parse()` 第 258 行 `result['title'] = title_text`——**抓第一個 `^(#+)\s+\S` 匹配的 line**（`#`、`##`、`###` 都吃）

**首行品質評估**：

| doc_type | raw markdown 首行典型 | 品質 | 原因 |
|---|---|---|---|
| academic | `# 論文標題` | 🟢 高 | 標準 IMRaD 封面 → MinerU 抓得到 |
| book | `# 書名` | 🟢 高 | 書籍封面通常完整 |
| technical | `# Contents` / `# 目錄` | 🔴 低 | 白皮書封面是 TOC，MinerU 第一個 # 就是它 |
| news | `# 新聞標題` | 🟢 高 | 標題層級明確 |
| web | `# 文章標題` | 🟡 中 | 視站台/版型而定 |
| resume | `# 候選人姓名` | 🟢 高 | 履歷頭通常清楚 |
| slides | `## 第 1 頁` | 🔴 低 | SlidesProcessor 從不寫 `#`（line 124-127 只有 `##`）；md_processor 抓第一個 `##` 當 title |

**信心度**：academic / book / resume / news = **high**；web = **medium**；technical / slides = **low**。

### A-2 metadata 軸（metadata_extractor）

**Schema v2（12 欄位）**：
```
title / translated_title / authors / publication_date / abstract /
journal_or_conference / doi / keywords / publisher / organization /
version / candidate_name   ← 4.7c step 2 新增
```
每欄位 `{value, source, confidence, alternates}`。

**三路抽取**：

| 路 | 階段 | 函式 | 觸發時機 | source 標籤 | 信心度 |
|---|---|---|---|---|---|
| 1 | Stage A-1 | `extract_pdf_metadata` (fitz) | pipeline 開頭、`pdf2md` 之前 | `pdf_metadata` | title=medium / authors=high / date=medium |
| 2 | Stage A-2 | `extract_metadata_from_first_page_llm` | 同上 | `llm_page1` | high |
| 3 | Stage A-merge | `merge_stage_a` | 同上 | `both_agree`（norm 後相等）/ `llm_page1 (conflict with pdf_metadata)`（衝突取 LLM） | high / medium |
| 4 | Stage B | `fill_abstract_stage_b` | 全 stages 結束、`upsert_paper` 之前 | `markdown_extracted` | high |

**4.7c step 3 後 doc_type 專用 prompt**：
- `prompt/processor/metadata_academic.txt`（含 candidate_name=null）
- `prompt/processor/metadata_resume.txt`（抽 candidate_name 為主、其他多為 null）
- `prompt/processor/metadata_technical.txt`（multi-page 看頭 3 頁、不排除 TOC）
- `book / news / slides / web` 暫共用 `academic` prompt

**對應 raw markdown 軸的對映**：

| doc_type | metadata title 期望可靠度 | metadata 對 raw 的修補力 |
|---|---|---|
| academic | 🟢 high | 一致時 both_agree；衝突時 metadata 勝 |
| book | 🟢 high | 同上 |
| technical | 🟡 medium-high（multi-page 看 3 頁） | **強**——raw 是 TOC 時、metadata 是真標題 |
| news | 🟢 high | 一致機會高 |
| web | 🟡 medium | 不一定一致 |
| resume | 🟢 high（candidate_name） | **強**——raw 可能是「履歷」字樣、metadata 是姓名 |
| slides | 🟡 medium（multi-page 未開但首頁 Vision 看得到） | **強**——raw 是「第 1 頁」、metadata 是真標題 |

### A-3 domain 軸（domain_detector）

**位置**：`pipeline_core._stage_detect_domain` (L534-539)，與 `analyze` 並行；輸出寫 `output_paths['_domain']`，最後寫進 `Paper.domain` 欄。

**內容**：自由文字短句（10-30 字），如「電力電子技術 - 高壓直流系統架構」、「體育新聞 - 環義自由車賽報導」、「植物分子生物學 - 多重營養逆境調控」。**不是 enum**、不要求字段固定。

**信心度**：LLM 看第一頁文字 + 圖片 → 通常很可靠（domain 是「粗粒度」判斷，LLM 容錯空間大）。失敗回空字串（soft fallback）。

**對 title / abstract 的合理性檢驗作用**：

| 場景 | domain | metadata title 候選 | 結論 |
|---|---|---|---|
| 一致 | 「電力電子技術 - 高壓直流系統架構」 | `800-VDC Architecture for AI Infrastructure` | ✅ domain 字串與 title 主題吻合 |
| 不一致 | 「植物分子生物學 - 多重營養逆境調控」 | `Contents` | ❌ domain 是真主題；title 是 TOC 雜訊 → log warning + 用其他 fallback |
| 不一致 | 「體育新聞 - 環義自由車賽報導」 | `User Guide` | ❌ 嚴重不一致 → fallback chain 觸發 |

但 domain **不是 title** 來源——它是「健康檢查」資料：不影響選誰當 title，但**可在 fallback 都失敗時用作 log 告警的證據**。

### A-4 三軸 × 7 doc_type 可靠度矩陣

| doc_type | raw markdown title | metadata title | metadata.candidate_name | metadata.abstract | domain | 衝突常見嗎 | 主要融合策略 |
|---|---|---|---|---|---|---|---|
| **academic** | 🟢 high | 🟢 high | N/A | 🟢 high（Stage B） | 🟢 high | ❌ 不常 | both_agree 即可，metadata 為主 |
| **book** | 🟢 high | 🟢 high | N/A | 🔴 無（書無 abstract） | 🟢 high | ❌ 不常 | metadata 為主、abstract 跳過 |
| **technical** | 🔴 low（TOC） | 🟡 med-high | N/A | 🟡 中（Executive Summary 可能） | 🟢 high | ✅ **常**（raw=TOC vs metadata=真標題） | **metadata 強制覆蓋 raw**（黑名單觸發） |
| **news** | 🟢 high | 🟢 high | N/A | 🔴 無 | 🟢 high | ❌ 不常 | metadata / both_agree |
| **web** | 🟡 medium | 🟡 medium | N/A | 🔴 無 | 🟡 medium | 🟡 視站台 | metadata 優先、raw fallback |
| **resume** | 🟢 high（姓名） | 🟢 high（candidate_name） | 🟢 high | 🔴 無 | 🟢 high | ❌ 不常 | **candidate_name 強制覆蓋** |
| **slides** | 🔴 low（「第 N 頁」）| 🟡 med | N/A | 🔴 無 | 🟢 high | ✅ **常**（raw 永遠是頁編號） | **metadata 強制覆蓋 raw**（黑名單觸發） |

**衝突類型歸納**：
- **A 類**（technical / slides）：raw 為「結構雜訊」（TOC / 頁碼），需 metadata 覆蓋
- **B 類**（resume）：raw 是姓名、metadata.candidate_name 也是姓名，**通常一致**；但若不一致（如 raw=「履歷」label、metadata=姓名），candidate_name 勝
- **C 類**（academic / book / news / web）：raw 與 metadata 通常一致，遇衝突取 metadata

## B. 融合決策流程（doc_type-agnostic 核心邏輯）

### B-1 title 融合（固定流程，不依 doc_type 客製）

```
INPUT:
  raw_title       = data['title']                  # md_processor 抓的
  meta_value      = metadata['title']['value']
  meta_confidence = metadata['title']['confidence']
  meta_alts       = metadata['title']['alternates']  # {pdf_metadata, llm_page1, ...}
  candidate_name  = metadata['candidate_name']['value']  # resume 用
  domain          = output_paths['_domain']
  doc_type        = output_paths['_confirmed_doc_type']

STEP 1: resume 短路
  if doc_type == 'resume' and candidate_name:
    return candidate_name                          # 信心度極高、直接用

STEP 2: 黑名單檢查（raw_title 為已知雜訊 → metadata 必勝）
  if raw_title in BLACKLIST or matches BLACKLIST_PATTERN:
    if meta_value: return meta_value
    if any v in meta_alts.values(): return v
    return None                                    # 觸發外層 fallback

STEP 3: 信心度比對（兩者都有值時）
  if meta_value and meta_confidence in ('high', 'both_agree'):
    if normalize(raw_title) != normalize(meta_value):
      return meta_value                            # 信心度高的 metadata 勝
    return meta_value                              # 兩者一致也用 metadata（語意明確）

STEP 4: raw fallback
  if raw_title:
    return raw_title

STEP 5: metadata low-confidence fallback
  if meta_value: return meta_value

STEP 6: 全失敗 → None（caller 接 original_filename / paper_uuid）

POST-STEP (sanity check, 不改 return 值):
  if domain and final_title:
    # 簡單啟發式：title 完全沒有任何 domain 短句字元 → log warning
    if no_lexical_overlap(domain, final_title):
      logger.warning(f"[md_restore] title='{final_title}' vs domain='{domain}' 主題不一致")
```

**黑名單初版（中英對照）**：
```python
TITLE_BLACKLIST_EXACT = {
    "contents", "table of contents", "目錄", "目次",
    "abstract", "摘要",
    "introduction", "前言", "緒論",
    "references", "参考文献", "參考文獻", "bibliography",
    "acknowledgements", "致謝",
}
TITLE_BLACKLIST_PATTERN = [
    r"^第\s*\d+\s*頁$",        # 第 N 頁
    r"^page\s*\d+$",            # Page N
    r"^chapter\s*\d+$",         # Chapter N
    r"^第\s*\d+\s*章$",         # 第 N 章
    r"^slide\s*\d+$",
]
```

`normalize` = lowercase + strip whitespace + trim punctuation。

### B-2 authors / candidate_name 融合

| doc_type | 來源 | 衝突解 |
|---|---|---|
| academic / news | `metadata.authors.value` 為主，無則 `data.authors_info` | metadata 勝；兩者皆空則無 authors 行 |
| resume | `metadata.candidate_name.value`（已在 B-1 step 1 短路）；authors 一律不寫 | — |
| slides / book | 通常無，跳過整行 | — |
| technical | 多無；若有 organization 取代 | — |
| web | 視情況；多無 | — |

### B-3 abstract 融合

| doc_type | 是否寫 abstract | 來源 |
|---|---|---|
| academic | ✅ | `metadata.abstract.value`（source=`markdown_extracted`、Stage B 抽出） |
| technical | 🟡 有則寫（Executive Summary） | 同上 |
| news / web / book / resume / slides | ❌ 不寫 | — |

**中英對應**：**目前是個洞**。`translate_processor.translated_abstract` 是 instance attr（line 19），翻譯後**只寫進對應 section content 的 `translated_content`**（不寫進 metadata、不寫進 JSON 頂層）。**Phase 4.7d 子工作**：
- Option 1（簡）：md_restore 內找 abstract section 的 `translated_content` 來注入
- Option 2（正規）：擴 metadata schema 加 `translated_abstract` 欄；translate_processor 寫進 metadata；md_restore 讀 metadata

推薦 **Option 1**（不動 schema、利用既有 JSON tree）。

**邊界規則**：
1. Header 與內文之間用 `\n\n---\n\n` 分隔（horizontal rule）
2. 「跳過原 first-#」實作：md_restore 改用 `sections` 開頭往後寫、不寫 `data['title']`——等同覆蓋原 first-# 來源
3. 若 metadata 完全沒值（極端 fallback）→ 整個 header section 跳過、寫回 `data['title']` 原路徑（與目前行為相同）

## Step 1-10 標準步驟（新增 doc_type X）

### Step 1: doc_type registry（7 處）
- 動 `web_server.valid_types` / `static.DOC_TYPES` / `DOC_TYPE_LABELS` / `doc_analyzer` 兩 dict / `translate_processor.style_hints` / `pipeline_core.extra_info_skip`（如 X 無 abstract）
- 每處上方有 marker `=== doc_type-registry ===`
- **必做**
- 工程量：15 分
- 驗證：`tools/check_doc_type_registry.py` exit 0

### Step 2: domain_detector
- domain_detector 為 LLM 自由判斷、**doc_type 無關**
- **fallback 即可**（不需動）
- 工程量：0
- 例外：若 X 為極特殊型態（如純圖文無文字），考慮在 detector 加 doc_type-aware logic——但目前 7 個 doc_type 都不需要

### Step 3: heading_fix prompt（doc_analyzer）
- 若 X markdown heading 結構特殊 → 寫 `prompt/doc/heading_fix_X.txt`
- 否則：dict reuse `'X': 'prompt/doc/heading_fix_academic.txt'`
- **多數 fallback 即可**
- 工程量：reuse 0 分；新寫 30-60 分（依 `prompt/doc/heading_fix_news.txt` 模板）
- 驗證：`tools/check_doc_type_registry.py` 確認檔存在

### Step 4: md_processor
- 通常**不需動**——「抓 first-#」對多數 doc_type 有效
- 例外：X first-# 策略不適用（如 slides 沒 H1，已透過 `SLIDES_DOC_TYPES` 處理 `collecting_authors`）
- 若 Step 8 md_restore 三軸融合做了，**md_processor 的 first-# 不準** **不再影響使用者可見結果**（被 metadata 覆蓋）
- **多數 fallback 即可**
- 工程量：0–30 分

### Step 5: metadata_extractor prompt
- 在 `prompt/processor/` 加 `metadata_X.txt`（依 `metadata_resume.txt` 模板）

## 一次處理所有 doc_type vs 分批

**推薦：一次處理**。理由：
1. 三軸融合**核心邏輯**（B-1 至 B-4）是 doc_type-agnostic 的，一次寫就涵蓋所有
2. doc_type-specific 只有 header template（B-5）—— 每個 30-50 行 template，7 個共 250-350 行，與核心邏輯同 commit 不算大
3. 分批反而每次都要動 md_restore，PR review 成本高
4. 既有 paper 不重生（無 migration 風險）

唯一例外：若 baron 對某個 doc_type 的 template 不確定 → 該 doc_type 暫 fallback academic、後續單獨 commit 微調。

## 既有 paper 處理

**不 backfill**。理由：
1. 既有 paper 跑過完整 pipeline、final_*_zh.md 已寫入
2. 重抽 metadata + 重跑 md_restore 成本高（fitz + 2× LLM + 寫檔）
3. user 仍可透過 P1 rename 手動覆寫顯示 title
4. 若 baron 需要少量舊 paper 補新格式：手動跑 `pipeline_core.process(..., existing_paths=...)` 只跑 md_restore stage 即可（pipeline 已支援 stage 列表機制）

## 風險點

| 風險 | 緩解 |
|---|---|
| 黑名單漏掉某 pattern → title 仍是雜訊 | 黑名單可後續迭代；fallback 鏈確保至少有 `original_filename` |
| LLM 抽 metadata.title 抽錯 → 寫進 markdown 開頭比 raw 更糟 | metadata.confidence == 'low' 時 fallback raw；保留 alternates 供查驗 |
| header template 與既有 markdown 內第一個 H2 重複 | 「跳過原 first-#」確認；測試 academic / news / book / web 三類「跳過」生效 |
| slides「不跳過 first-#」例外可能誤判 | 顯式以 doc_type 決定 skip_first_heading；不靠啟發式 |
| translated_abstract 注入位置不對 | C-1 工作走「讀 JSON tree 內 abstract section 的 translated_content」、不動 schema 是最低風險路徑 |
| 既有 final 檔不重生 → 新舊顯示不一致 | 預期行為；UI 不會壞，只是新 paper 開頭品質更好；舊 paper 待 user override 或選擇性重跑 |
