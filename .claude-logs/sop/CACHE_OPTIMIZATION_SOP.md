> 本文件為快取友善度評分機制的權威 SOP 規範，用以維護全專案 Markdown 文件的 Prompt Cache 效率。

## §1 評分演算法（Scoring Algorithm）

快取友善度採用 100/50/0 三級評分制，以評估文件對 LLM Prompt Cache 的快取命中效率：

### 1.1 綠牌（100 分，最優快取）
- **判定條件**：
  1. 文件頂部 `# 標題` 後直接是靜態的 `## §0 改版規則` 區塊（3 行內）。
  2. 頂部前 20% 行內**無任何高頻變動**內容。
  3. 所有動態欄位（如 Revision、更新日期、Commit Hash、變動日誌等）**強制放置在文件最後 10% 行**（即尾部 §99 之後）。
- **快取效果**：最優。頂部大量靜態內容保證了前置 Cache 塊能被 100% 命中且長時間保持有效。

### 1.2 黃牌（50 分，快取退化）
- **判定條件**：
  - 文件中段或前段包含任何變動日期、Revision、臨時任務編碼或時間戳記。
- **快取效果**：中等。每次微調變動日期都會導致該行之後的所有內容 Cache 全數失效（Cache Miss）。

### 1.3 紅牌（0 分，無快取效率）
- **判定條件**：
  - 文件頂部前 20% 行內包含高頻變動內容（如每次必填的 Commit Hash、當前任務 ID、今日日期等）。
- **快取效果**：極差。每次 session 或 commit 都會引發頂部 Cache invalidation，造成高昂的 API Token 與延遲開銷。

## §2 評分排除名單（Exclusions）

為防範誤判，以下頻繁變動之系統級與報告類文件自動列入評分排除名單，不計紅牌：
1. `TODO.md`（任務狀態真理源，頻繁變動）
2. `prompts/` 目錄下的所有提示詞歸檔文件（包含 timestamp 與任務變數）
3. `report/` 目錄下由腳本產出的診斷報告

---

## §3 評分結果存放路徑

評分報告必須輸出至專屬目錄，**嚴禁污染被評分文件本身**：
- 報告路徑規格：`.claude-logs/report/<YYYY-MM-DD>_CACHE_FRIENDLINESS_REPORT.md`

---

## §4 觸發時機

1. **自動掃描**：Antigravity 掃描全 codebase 時觸發（建議週級執行）。
2. **人工觸發**：開發者或負責人（baron）下達核查指令時手動觸發。

---

## §5 第一輪評分範圍

本 SOP 落地後，第一輪評估應鎖定以下 4 個核心治理文件：
1. `.claude-logs/ref/PROJECT_PROGRESS_CONTROL_FRAMEWORK.md`

3. 既有 `.claude-logs/sop/2026-05-23_logging_SOP_手冊.md`（若存在）
