## D. JavaScript 行為差異

> prototype 的 `<script>`（1271–1762）為**純展示**：三欄收合、popup 錨點
> 定位、tooltip 系統、modal 系統(ESC/Tab/mask)、自訂 dropdown、主題切換、
> web-search placeholder 同步、active demo。**無任何 fetch / EventSource /
> 業務邏輯**。真正業務 JS 全在現役 index.html（602–1357）。

- **現役有、prototype 無對應 DOM 的 handler**
  - `#send-btn.onclick = sendMessage`：prototype 無 send-btn → 需改為僅
    Ctrl+Enter 觸發（現役 chat-input 已有 keydown Ctrl+Enter；只是 send-btn
    被當「鎖串流」的對象，需改鎖 chat-input / 旗標）。
  - `doc-type-select.value`：→ 讀 `#doc-type-dropdown[data-value]`。
  - native `confirm()`/`alert()`/`prompt()`（deletePaper / cleanup /
    folderCreate / folderRename / folderDelete）：prototype 提供
    `customConfirm/customAlert` + `#action-modal/#notice-modal`；`prompt()`
    無對應替身（folder 改名/新增用 prompt）→ 需自備輸入 modal 或保留 prompt（→ G）。
  - native `title=` tooltip：全面改 `data-tip` + 接 prototype tooltip 系統。
- **prototype 有的互動、現役無對應後端 / 邏輯**
  - `.paper-item.uploading` 占位列：api-integration §4 明列「原版更新
    `#upload-btn` 文字；prototype 規劃改更新 `.paper-progress-*`」——
    SSE `processing` handler 的 DOM 目標需重寫（後端 payload 不變）。
  - `.msg-regen` 重新生成：無接線（可重用 `POST chat`，前端邏輯）。
  - `#theme-*`：純前端 + localStorage（key `madpro-theme`）。
- **SSE / fetch 邏輯本身無變**：endpoint、payload、`{done:true}` 收尾、
  grounding_sources、status 三態（processing/done/error）、`progress.index>=10`
  → reading_ready 自動 loadPaper 等規則，api-integration 與現役一致；
  改的是**收到事件後操作哪個 DOM**，非 fetch 流程。
- **localStorage**：現役用 `foldersOpen`；prototype 另加 `madpro-theme`。
  兩者不衝突。

## E. 套用方案建議（三層）

> 共同前提：先做 F 備份。所有層皆「以現役 index.html 的業務 JS 為地基，
> 把 prototype 的結構/樣式/展示 JS 疊上」，**不是反向**（規範也要求以
> index.html 為準）。

### 層 1 — 最小套用（樣式 + 主題，邏輯全留）
**目標**：換結構 CSS + 主題系統 + 三欄/底部/header 重排版，業務 JS 全保留。
- 改動檔：`static/index.html`（單檔）、新增 `static/themes/*.css`（4 檔，
  從 design/new/themes 複製、`@import` 字型路徑確認）、`web_server.py`
  **不改**（StaticFiles 已能服務 `/static/themes/`）。
- 必做：① 移植 prototype 結構 CSS 進 `<style>` ② 加
  `<link id="theme-link" href="/static/themes/kahn.css">`（置 `</style>` 後）
  ③ 三欄/sidebar-bottom/chat-header DOM 重排（toggle 入 header、upload→
  icon-only、send-btn 取捨見 G）④ 全 icon 改 stroke 1.5 / 去 inline style
  / 加 `data-tip` ⑤ 接 prototype 的 tooltip + modal + popup-anchor 展示 JS
  ⑥ 保留全部 fetch/SSE/state JS，只改被 DOM 重構影響的選擇器
  （send-btn、doc-type、tooltip、native dialog）⑦ 刪 `#demo-bar` 與 demo handler。
- 工程量：**大（>120 分）**——單檔但 1358↔1764 行整併、CSS 全換、JS 選擇器
  逐一校對、icon 全改。
- 風險：① 業務 JS 對 `#send-btn`/`doc-type-select`/native dialog 的依賴點
  漏改 → 上傳/刪除/問答中斷 ② 主題 CSS 字型需外網（離線環境破版）
  ③ token 化不完全仍留硬編色 ④ `.paper-item.uploading` 若此層先不做，
  上傳進度 UI 需暫留現役「upload-btn 文字」邏輯（混風險）。
- 可拆 commit：(a) 備份+主題檔落地 (b) 結構 CSS 換 (c) DOM 重排+icon
  (d) tooltip/modal/popup 展示 JS (e) 業務 JS 選擇器校正 (f) 刪 demo。

### 層 2 — 中度改造（加 prototype 新互動，後端不變）
層 1 +：
- `.paper-item.uploading` 占位列：JS 動態建列、SSE `processing` 改寫
  `.paper-progress-text/-fill`、`done` 換真列（後端 payload 不變）。
- `customConfirm/customAlert` 取代 native confirm/alert；folder prompt →
  自訂輸入 modal（或暫留 prompt，見 G）。
- 自訂 `#doc-type-dropdown` 取代 native select。
- `#theme-modal` 切換 + localStorage 持久化（無後端）。
- 改動檔：`static/index.html`（+ themes）；`web_server.py` 不改。
- 工程量：**大（>120 分）**（在層 1 之上再疊互動，累加）。
- 風險：upload SSE DOM 重寫最容易回歸（牽動 reading_ready 自動 loadPaper、
  done 重抓清單、isProcessing 鎖）；自訂 dropdown 鍵盤/焦點需符 components。
- 可拆 commit：每個互動一個 commit（uploading 列 / custom dialog /
  dropdown / theme）。

### 層 3 — 完整套用（新 API + 新功能）
層 2 +（需後端，逐項可獨立）：
- 刪除對話：`DELETE /api/papers/{id}/chat/history`（paper_manager 已有
  `delete_conversations`，web_server 缺路由）→ 啟用 popup「刪除對話」。
- 論文改名：擴 `PATCH /api/papers/{uuid}` 吃 `title/translated_title`
  + popup 入口。
- `.msg-regen` 重新生成：前端重送 `POST chat`（多半免後端）。
- 主題跨裝置：`GET/PATCH /api/user/preferences`（需 DB user 欄；最大）。
- 改動檔：`static/index.html`、`web_server.py`、可能 `paper_manager.py`/
  `models.py`（preferences/rename）。
- 工程量：刪除對話 **中（30–120）**；改名 **中**；regen **小**；
  preferences **大**（DB schema + 登入讀取）。
- 風險：動到後端與 DB，回歸面大；建議每功能獨立 PR、各自端到端。
- 可拆 commit：四功能各自獨立（互不依賴）。
