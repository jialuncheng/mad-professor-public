## §4 真因

對應 plan §3：

1. **`llm/client.py:48` + `config.py:22`** 兩處 `genai.Client(api_key=GEMINI_API_KEY)` 零 `http_options` 參數
2. SDK 預設 httpx transport 無顯式 timeout → 卡 read 風險（socket 永不 return）
3. LLMClient + EmbeddingModel 各自獨立 `genai.Client`、無共享 httpx.Client → TCP handshake 重複（台灣 → Gemini us 端點 ~300ms 額外延遲）+ keepalive pool 失效
4. **既有 `llm/retry.py`** 用 `delay = base * (2 ** attempt) + random.uniform(0, 1)` 是「指數退避 + 0-1 秒線性抖動」、不是「全隨機抖動」(`t_wait = random(0, min(t_max, base*2^attempt))`)
5. **演進**：17-1b `asyncio.to_thread` 已解 event loop 阻塞；但底層 socket 卡 read 仍會耗盡 thread pool worker（max ~32）→ baron 觀察過 SSE 卡死 + `httpx.RemoteProtocolError` 偶發

baron OrcStack 端 Gemini 3 Pro Preview Vision call 多頁時 30-90s latency、無 read timeout 防護 → 偶發症狀疊加。

### 5.4 `llm/retry.py` Full Jitter 公式

新增 module-level：
```python
import os
MAX_BACKOFF_SEC = float(os.environ.get("LLM_RETRY_MAX_BACKOFF", 60.0))
```

`retry_call` + `retry_stream` 各 1 處改寫：
```python
# 原:
# delay = base * (2 ** attempt) + random.uniform(0, 1)

# 改為:
exp_window = min(MAX_BACKOFF_SEC, base * (2 ** attempt))
delay = random.uniform(0, exp_window)
```

語意：
- attempt 0: `random(0, min(60, 2)) = random(0, 2)` 秒
- attempt 4: `random(0, min(60, 32)) = random(0, 32)` 秒
- attempt ≥ 5: cap 在 60s

token-based retryable 偵測（`_RETRYABLE_TOKENS`）**完全不變**——`RemoteProtocolError` / `disconnect` / `closed` / `reset` 等 token 繼續抓。
