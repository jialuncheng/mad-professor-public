### 面板 padding / 標題列
- 左欄 `#sidebar h1`：**height 48px 固定**、padding `0 16px 0 44px`（左 44px 讓位浮動收合鈕）
- 右欄 `#chat-header`：**height 48px 固定**、padding `0 44px 0 16px`、flex space-between
- 中欄 `#content-toolbar`：**無固定高度**，padding `12px 24px`（高度由內容決定，≠48px）
  → G3 要求三欄標題列一致 48px，**中欄目前不符**，需正規化。
- `#sidebar-bottom`：flex 橫排、padding 12px、gap 8px、min-height 68px（5 顆橫排塞爆＝跑版主因）
- `#chat-input-area`：flex、padding 12px、gap 8px、min-height 68px、align-items center
- `#chat-input`：flex:1、min-height 44px、max-height 120px、resize:none、overflow-y auto（**固定高，長輸入看不全**）
- `.panel-toggle`：position:fixed top:10px 28×28（即使用者說的「紫色框」＝左欄收合鈕浮在 h1 左側）

## ② 既有 tokens 是否足夠
不足。缺「按鈕系統」語義 token。建議**新增語義別名（不新增新數值，全部對映既有 --space-）**：
- `--btn-h: 32px`（取代散落的 height:32px）
- `--btn-pad-x: var(--space-4)`（文字鈕水平內距 16）
- `--btn-min-w: 52px`（黃金比 ≈32×1.618，文字鈕最小寬，整數取 52）
- `--btn-icon: 32px`（icon-only 正方）
- `--toolbar-h: 48px`（三欄標題列統一）
- `--pad-panel: var(--space-4)`（面板內邊 16）
- `--gap-btn: var(--space-2)`（按鈕族間距 8）
僅 `--btn-min-w 52` 與 `--btn-icon` 為新數值（皆由規範推導，非任意），其餘全是既有 space 的語義包裝
→ 風險低、可被既有規則漸進採用。

## ③ 改動策略
- **CSS 為主**：G1/G2/G3（按鈕/邊距/標題列規範）、F（移除 icon 多為刪 inline SVG）、
  I1（兩鈕同寬）、E 的樣式部分、I4（標題列高度一致）→ 幾乎純 CSS + 刪 SVG 標記。
- **HTML 結構改動（小範圍、需謹慎）**：
  - I3 左欄底部分兩排：`#sidebar-bottom` 內需包成「上排次要鈕 / 下排上傳鈕」兩個 row 容器
    （新增 2 個 wrapper div）。
  - I2 搬「搜網」：把 `#web-search-toggle` 節點從 `#chat-input-area` 移到 `#chat-header`，
    改名「開啟搜尋」。
  - I5 textarea 自動長高：加 input event listener（JS）+ 放寬 max-height。
- **JS**：僅 I5 新增 listener；I2/I3 是 DOM 位置搬移，事件以 `getElementById(id)` 綁定，
  **只要 id 不變、元素仍存在，listener 不受影響**（getElementById 在 listener 綁定時才查，
  搬 DOM 不影響）。

## ④ 副作用與風險
1. **icon-only 按鈕拿掉 icon＝空白鈕**（最高風險）：`#new-folder-btn / #help-btn /
   #cleanup-btn / #logout-btn / .delete-btn`（甚至 print/export）目前**只有 SVG 沒有文字**，
   單純刪 SVG 會變空按鈕。G4 拿 icon 必須**同時補文字 label**（說明/清理/新資料夾/登出/刪除/
   列印/匯出 MD），否則不可點識別。此為 F 階段的硬相依，需與按鈕文字一併規劃。
   `.delete-btn`（每筆論文 hover ×）改文字「刪除」會變寬、影響 paper-item 版面，
   建議該顆**例外保留為符號或用「刪除」短字**（需取捨，標記待確認）。
2. **token 改動影響面**：`--btn-h` 等被 primary/ghost 兩大群組共用，一改全站按鈕同步變動；
   優點是統一，風險是任何個別微調都會擴散 → 建議規範 token 定稿後才套，套用時逐群組目視。
3. **DOM 搬移 vs JS listener**：I2 搬 `#web-search-toggle`、I3 重組 `#sidebar-bottom`，
   所有 handler 皆 `document.getElementById('...').onclick=` 形式（綁定當下查 DOM），
   搬節點不破壞；但需確認搬移**不改 id**、且 `.btn-ghost.active` 樣式（搜網開關狀態）
   在 chat-header 內仍適用（class 不變即可）。`web-search-toggle` 的狀態變數 useWebSearch
   與 sendMessage 讀取邏輯不受位置影響。
4. **textarea 自動長高 vs SSE**：SSE 串流寫入的是 `#chat-messages`，與 `#chat-input` 無關；
   `sendMessage` 送出後 `input.value=''` → 需在送出後一併**重置 textarea 高度**，否則殘留高。
   `#chat-input-area` 為 min-height 不是固定 height，textarea 長高會撐高輸入區（OK）；
   但 `align-items:center` 在多行時送出/搜尋鈕會置中於高框中央，視覺建議改 `flex-end`
   （標記為 E 的設計細節）。autogrow 用 scrollHeight，需先 `height='auto'` 再設，
   並設定 1 行 min（~32–36px，含 padding）/ 5 行 max（依 line-height 計，超出 overflow-y:auto）。
5. **中欄標題列非 48px**：`#content-toolbar` 目前高度由 padding 撐出（≠48），G3 正規化為
   `--toolbar-h:48px` 後，其 padding 由 `12px 24px` 改為水平 16、垂直靠 flex 置中，
   視覺位移需確認 `#current-title`（flex:1 省略）與兩鈕對齊。
6. **RWD**：全站僅 `@media print`，無響應式。本次不做 RWD，但 I3 兩排化會增加左欄底部高度，
   需確認 `#sidebar` flex 直欄在小高度視窗不擠壓 `#folder-tree`/`#paper-list`
   （兩排 sidebar-bottom 高度上升，folder-tree 已 max-height:38%，paper-list flex:1 會吸收）。
7. **print 媒體查詢**：`@media print` 隱藏 `#print-btn #lang-toggle`，改 class/結構時別破壞
   該選擇器（仍以 id 命中即安全）。

## ⑤ 階段拆解（每階段獨立可運作、可中斷）
- **Phase A — tokens 統一規範（G1/G2 基礎）**：:root 增語義 token；把 primary/ghost 兩群組
  的 height/padding/min-width 改引用 token。零結構、零 JS。風險最低、為後續基礎。
- **Phase B — 標題列正規化（G3/I4/I6）**：三欄標題列統一 `--toolbar-h:48px`、水平內距 16、
  flex 置中兩端對齊；中欄補固定高；確認浮動收合鈕對齊。純 CSS。
- **Phase C — 左欄底部分兩排（I3）**：`#sidebar-bottom` 拆上排（說明/新資料夾/刪除/登出）
  + 下排（上傳 flex:1）。HTML 加 2 wrapper + CSS；id 不變故 JS 不動。
- **Phase D — 搜尋開關搬右欄 header（I2）**：移動 `#web-search-toggle` 節點到 `#chat-header`、
  文案改「開啟搜尋」、套標題列按鈕規格。HTML 搬移；JS id 不變不動。
- **Phase E — textarea 自動長高（I5）**：CSS 放寬 max-height + JS input listener + 送出後重置。
  局部、與其他階段無耦合。
- **Phase F — 移除 icon（G4/I1）**：刪 inline SVG、icon-only 鈕補文字 label、
  中欄兩鈕（lang/print）同寬、上傳保留＋。**相依：必與按鈕文字決策一起做**。

## ⑥ 建議執行順序（依相依與風險）
1. **Phase A**（tokens）：最低風險、純加 token 與引用，後續全部依賴它的尺寸規範。
2. **Phase B**（標題列）：依賴 A 的 --toolbar-h/--pad-panel；純 CSS、可視。
3. **Phase F**（移 icon＋補文字）：依賴 A（按鈕尺寸）；獨立性高但影響每顆鈕外觀，
   早做可讓後續 C/D 直接用「最終文字鈕」排版，避免重排兩次。`.delete-btn` 文字化取捨先確認。
4. **Phase C**（左欄兩排）：依賴 A/F（鈕已定稿尺寸與文字）→ 排版一次到位。
5. **Phase D**（搜尋開關搬家）：依賴 B（chat-header 規格已定）；DOM 搬移＋文案。
6. **Phase E**（textarea autogrow）：完全獨立，可任何時候插入，建議最後（不阻塞其他）。

相依鏈：A → B → F →（C, D）→ E。每步完成系統可正常運作；A/B/F 為純樣式，C/D 為小範圍
DOM 重組（id 不變，JS 安全），E 為孤立增強。
