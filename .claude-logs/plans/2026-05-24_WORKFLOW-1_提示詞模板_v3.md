## 附錄 A：模板使用 FAQ

### Q1：四類工作流我自己分不清怎麼辦？

依規劃書 §6.1 Q7 推薦：先由 Claude Code 提議、baron 確認後才執行。具體方法：

baron 給 Claude Code 一個「分流提示詞」：
```
你好 Claude Code。
這份規劃書 <檔名> 你判斷是哪一類工作流（FE-Refactor / BE-Refactor / FE-Hotfix / BE-Hotfix）？
給你的判定理由（grep 證據）、預期 commit 數、影響程度評估。
不要產執行計劃、只回答分類。
```

Claude Code 回應後、baron 用對應模板（A-FE / A-BE / C-FE / C-BE）正式啟動。

### Q2：跨前後端的中型改動（例如新增 API + UI）怎麼分類？

走 **BE-Refactor lead**（後端為主、前端為輔）、在執行計劃 §0「工作流類別」標註：
```
工作流類別：BE-Refactor（lead）+ FE-Refactor（sub）
```
落地時 commit 拆分可以「先 BE → 後 FE」、各自獨立可逆。

### Q3：模板 A-FE 跟 A-BE 我可以合併用一個模板嗎？

可以、但會浪費 token——A-FE 不需要讀 logging / database SOP、A-BE 不需要讀 design/docs。分流的核心目的就是節省 token。

### Q4：執行報告附 commit message、baron 手動 commit 後該怎麼處理？

1. baron 執行 `git commit -m "<報告附的 message>"` + `git push`
2. 把 commit hash（前 7 碼）回填到執行報告 §「落地 Commit 表格」
3. 視需要把該 commit hash 告知 Antigravity 跑模板 D
4. 更新 TODO.md（從 🟡 WIP → ✅ done、搬到「已完成」表格、更新類別索引）

### Q5：模板 D 一定要 Antigravity 才能跑嗎？Claude Code 自驗證不行？

不行。第三方驗證是「防 Claude Code 自我背書」的關鍵防線；自我驗證 = 沒驗證。

### Q6：改版規劃書一定要先有嗎？baron 直接給提示詞不行？

可以、但會破壞雙軌制：
- 大改版 / 新功能 / 多 commit 任務 → 先有改版規劃書（套 template_revision_plan.md）→ 用模板 A-FE / A-BE
- 小修補（< 10 行、單 commit）→ 直接用模板 C-FE / C-BE hotfix、無需規劃書

### Q7：v3 後、Claude Web 完全退場、若 baron 不會寫提示詞怎麼辦？

baron 從本檔的 5 個模板中選對應的、複製、填變數即可。每個模板末尾都有「本次任務變數」清單、照填就完成。

### Q8：如果引入 Logseq、提示詞模板需要怎麼調整？

不需要調整。Logseq 不影響提示詞文字、只影響 baron 自己的文件閱讀 / 跨檔連結 / 標籤管理體驗。
