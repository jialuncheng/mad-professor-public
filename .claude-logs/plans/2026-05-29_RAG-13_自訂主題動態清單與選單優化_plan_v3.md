# 2026-05-29_RAG-13_自訂主題動態清單與選單優化 plan

## §1 TL;DR（概要）

- **挑戰**：目前網頁的主題下拉選單為前端純靜態寫死。上傳自訂 CSS 主題時，僅暫存在前端 JS 閉包記憶體中；一旦頁面 Reload，除了當前已套用的單一主題可從 localStorage 復原外，其他已上傳的自訂主題全部丟失，且點選選單時完全沒有 API 動作。
- **解法**：
  1. 後端 `web_server.py` 新增 `GET /api/themes` 路由，動態掃描 `static/themes/` 內所有自訂 `.css` 檔案，合併內建主題回傳包含 `custom` 與 `updated_at` 的主題 JSON 列表。
  2. 前端 `static/index.html` 的 `dropdownAPI` 增加 `setThemes()` 介面，並在頁面載入時發起非同步 `fetch('/api/themes')` 請求，套用「內建主題 ➔ 自訂主題（時間由新到舊）」的分組排序逻辑（方案一），且在自訂主題區上方渲染視覺分隔線。
  3. 測試端修改 `tests/test_themes_upload.py` 既有 `test_client` fixture，並行掛載 `GET /api/themes` endpoint，保障測試環境的路由連通性。
- **影響**：新增 `GET /api/themes` 接口，對其他既有 RAG/Chat/Paper 模組與 DB Schema 無任何 runtime 影響。

## §2 目標規格

### 1. 後端主題查詢 API 規格
* **路由**：`GET /api/themes`
* **回傳值**：JSON 陣列。
  - 項目屬性包含：`name`（代碼）、`label`（顯示名稱）、`custom`（是否為上傳自訂，布林值）、`url`（檔案路徑）、`updated_at`（修改時間戳，float）。
  - 對於內建主題（mies, kahn, kandinsky, nara），`custom` 設為 `false`，`updated_at` 設為 `0.0`。
  - 對於自訂主題，讀取其 `st_mtime` 作為 `updated_at`。

### 2. 前端選單動態載入與分組排序（方案一）
* **動態更新**：頁面初始化載入時、以及成功上傳主題後，均觸發非同步拉取後端 API 並刷新選單。
* **分組排序邏輯**：
  - **系統內建組**：固定置頂，順序保持 `Mies van der Rohe` ➔ `Kahn · Kimbell Art Museum` ➔ `Kandinsky · Bauhaus` ➔ `Yoshitomo Nara`。
  - **視覺分隔**：若自訂主題列表非空，在其上方渲染一條細水平線與 `自訂主題` 小字標籤，保持 MadPro 高質感 UI。
  - **分隔線樣式防禦（🔴 盲點 A 修正）**：分隔線 background 優先使用 `var(--color-divider)`，並強烈建議設置 `var(--color-border)` 作為 fallback，以防極簡主題未定義 divider 變數：
    `background: var(--color-divider, var(--color-border))`
  - **使用者自訂組**：依據 `updated_at` 時間戳進行**由新到舊（最新上傳排最前）**排序。
  - **雙重初始化更新（🟢 盲點 D 認證）**：為避免載入時閃爍，前端先透過 localStorage 同步更新當前主題，再非同步向 server 獲取最新主題標籤。由於自訂主題的顯示 label 預設與檔名（stem）一致，前後更新的值一致，不會產生視覺閃爍。

+                        "label": name,
+                        "custom": True,

+                    })

### §7.2 手動端到端（E2E）驗證流程
1. **上傳主題驗證**：進入系統，點選風格 modal，上傳一個 `mystyle.css` 自訂主題檔案。
2. **選單即時呈現**：點擊風格下拉選單，觀察是否正確出現「自訂主題」分隔標記，且下方包含 `mystyle` 的按鈕。
3. **頁面重整（Reload）防護驗證**：
   - 點擊 F5 重新整理瀏覽器。
   - 再次打開風格 modal ➔ 點選下拉選單，檢查 `mystyle` 依然完好存在於下拉清單中，且分組分隔線顯示正確，沒有退回原始四項。
