# 2026-05-19 done 後自動回填論文標題（純前端最小修正）

## 任務
trackProgress 在 `progress.index >= 10` 自動 `loadPaper(paperId, '（內容已就緒，AI 問答準備中）')`，
但 `status === 'done'` 時只 `enableChat()`，未更新標題，導致工具列停留在佔位字串。
要求：done 後回填真實標題，不得重新 fetch 已載入內容，NEVER 改其他邏輯。

## 修改位置
- 檔案：`static/index.html`（唯一變更檔）
- 函式：`trackProgress` 的 `data.status === 'done'` 分支
- 變更：`loadPapers()` → `loadPapers().then(() => { ... })`，於側欄重建完成後，
  若 `currentPaperId === paperId`，讀取
  `.paper-item[data-id="<paperId>"] .paper-title-zh`（= 後端 `translated_title || title`）
  的 `textContent`，寫入 `#current-title`。
- 其餘 done 分支邏輯（chat-panel 展開、removeReadingReadyMessage、enableChat、loadChatHistory）原樣保留。

## 行為說明
- 真實標題來源 = 已存在的 `loadPapers()` 那一次 `/api/papers` 抓取結果（papers_index），
  不額外打 API、不重 fetch `/content`。
- 僅更新 `#current-title` 的 textContent；內容區 DOM 不重繪。
- 只在使用者正看著該篇（`currentPaperId === paperId`）才回填，避免覆蓋使用者已切到的其他論文標題。
- `loadPapers()` 仍非阻塞；標題回填掛在其 `.then()`，確保側欄 DOM 已重建後才讀取。
- 找不到節點（理論上 done 後 papers_index 必有該筆）則安全跳過，不報錯。

## 驗證
- 抽出 inline `<script>` 後 `node --check` 通過。
- `git diff --stat`：僅 `static/index.html`，後端零變動（pipeline_core / paper_manager / ai_core / web_server / SSE / papers_index 寫入時機 / 階段順序 皆未改）。

## 疑慮
- 標題回填依賴側欄項目 class `.paper-title-zh` 與 `data-id` 結構；若日後 `loadPapers()`
  的 DOM 結構調整需同步此選擇器（已於程式碼註解標明用途）。
- 若 `done` 事件時使用者剛好切到別篇（`currentPaperId !== paperId`），不回填——預期行為，
  該篇下次由側欄點選時 `loadPaper` 會帶正式標題。
