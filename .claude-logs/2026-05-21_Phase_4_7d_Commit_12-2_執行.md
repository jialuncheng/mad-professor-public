## 修法

### 1. 新增 `llm/client.py`（207 行）

從 `config.py` L13-192 整體搬出 `class LLMClient`：

- **import 改動**：
  - 從 `settings` 直接取 `CHAT_MODEL` / `GEMINI_API_KEY`（避免循環 import config）
  - 從 `llm.message_utils` 取 `_convert_messages`
  - 從 `llm.retry` 取 `retry_call` / `retry_stream`

- **套 decorator**：
  - `@retry_call(retries=3, base=2.0)` on `chat` / `chat_with_image`
  - `@retry_stream(retries=3, base=2.0)` on `chat_stream_by_sentence`

- **`chat_with_image` 既有 429 retry 內迴圈拔掉**：
  - 移除 `import time` / `for attempt in range(3):` / `try/except '429'` / `time.sleep(2 * (attempt + 1))`
  - 改為直接呼叫 `self.client.models.generate_content(...)` + `return response.text`
  - retry 由 `@retry_call` decorator 統一管（涵蓋 5xx / 429 / timeout / connection）

- **`chat_stream_by_sentence` 內部 grounding fallback 完全不動**：
  - L143-159 內部 `try/except` + `yield from _run(False)` 保留原樣
  - 與 `@retry_stream` 兩層獨立：decorator 只 cover「進 generator 前 / 第一 yield 前」例外；grounding fallback 在 generator 內處理 grounding 特定失敗

- **保留**：singleton get_instance、`_last_grounding_sources` side-channel、所有 signature

## 風險與如何處理（依 plan §5）

### 5.1 caller 漏改
- **狀態**：✅ 已 grep 確認 9 處 callers 全改完、`from config import LLMClient` 程式碼路徑 0 命中
- 唯一殘留是 `llm/client.py` docstring 內提及舊路徑作為遷移說明（不是 code，無影響）

### 5.2 循環 import
- **狀態**：✅ `llm/client.py` 從 `settings` 取常數（非 config）；`llm/message_utils` / `llm/retry` 都不 import config——無循環

### 5.3 stream + grounding fallback 兩層 retry
- **狀態**：✅ 兩層獨立。`@retry_stream` 在 generator 進入前 / 第一 yield 前 cover；grounding fallback 在 generator 內處理 grounding 特定失敗。順序：
  1. 外層 decorator 啟動 generator
  2. 進入 `chat_stream_by_sentence`、跑 grounding logic
  3. grounding 失敗 → fallback to no-search（內層處理）
  4. no-search 也炸、且尚未 yield → decorator 重啟整個 method（外層處理）
- 已被 12-1 `test_retry_stream_pre_yield_retry` / `test_retry_stream_mid_stream_no_retry` 覆蓋核心行為（不重複加整合測試）

### 5.4 decorator 影響 stack trace
- **狀態**：✅ `@functools.wraps` 保留原函式 metadata（在 12-1 `retry.py` 內已用）；caller 端 except 行為等效（例外型別不變）

### 5.5 chat_with_image 既有 429 retry 拔除後行為差異
- 原本：固定 sleep 2s / 4s / 6s、3 attempts、僅擋 '429'
- 現在：指數退避 ~2.5s / 4.5s / 8.5s（jitter 固定 0.5 估算）、3 attempts、擋 5xx / 429 / timeout / connection / unavailable / deadline
- **改善**：涵蓋更廣（5xx 也擋）、退避稍長給 server 更多時間
- **風險**：總等待時間略增（max ~15s vs 舊 12s）——可接受
