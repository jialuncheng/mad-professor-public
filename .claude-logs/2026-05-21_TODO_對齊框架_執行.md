## §3 新加項目（本 session 新發現）

### 🔴 RAG-8 md_restore / translate table 渲染 bug

- **觸發背景**：本 session 過程中 baron 觀察 DeHunt 學歷 + slides 樣本 `final_*_zh.md` 內 `<table>` 的 `<tr>` 之間多插空行、前端 markdown 渲染破碎成多塊
- **真因推測**：`processor/md_restore_processor.py::_process_section()` 或 `processor/translate_processor.py` chunk 邊界用 `\n\n` 分隔、注入空行
- **修法方向**：先 diagnose（看 raw `_translated.json` vs `final_*_zh.md` 差異定位是哪 stage 注入），再決定改 md_restore section join 邏輯 / translate chunk boundary
- **工時**：先 diagnose 1 commit、修法 1-2 commits
- **影響範圍**：所有含 table 的 doc_type（academic、resume、book）渲染品質

### 🔴 RAG-9 markdown `~` 字元被誤判刪除線

- **觸發背景**：本 session 黃忠偉履歷 `100~500人` / `2003/8~仍在職` 等 tilde 範圍語法在前端顯示時被視為 GFM `~~text~~` 刪除線格式
- **真因**：前端 markdown 渲染器（marked.js 或同等）啟用 GFM strikethrough
- **修法方向**：
  - 選項 A：前端 marked.js options 關閉 `gfm.strikethrough`
  - 選項 B：後端對單一 `~` escape 成 `\~`（影響面廣、會污染翻譯內容）
  - 推薦 A（前端調 option 只影響渲染、不污染資料）
- **工時**：30 分鐘（marked.js options 改 + 6 份履歷 + 數份 academic 樣本回歸測試）
- **影響範圍**：含日期範圍 / 數值範圍的內容（履歷尤其常見）
