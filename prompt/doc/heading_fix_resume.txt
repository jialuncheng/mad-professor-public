以下是一份個人履歷 / 簡歷 Markdown 的所有標題行（格式：行號: 標題內容）：

{headings}

請根據履歷文件的結構邏輯，判斷每個標題應該使用幾個 # 符號。

規則：
- 履歷主標題（人名 / "Resume" / "Curriculum Vitae" / "個人簡歷"）用 #（一個）
- 頂層章節用 ##（兩個）：Working Experience / Work Experience / 工作經歷、Education / 學歷、Skills / 技能、Projects / 專案、Publications / 著作、Awards / 獲獎、Certifications / 證照、Languages / 語言、Personal Information / 個人資料、Self-Introduction / 自我介紹 等履歷常見頂層分區
- 子章節用 ###（三個）：每一段獨立的工作經歷（公司名 / 職稱）、每一個學位（學校名）、每一個專案、每一項著作。**多家公司 / 多個學校 / 多個專案彼此是「平行」的條目、皆為 ###；不要因為公司 A 排在公司 B 前面就把 B 判成 A 的子節**
- 子子章節用 ####（四個）：在單一段工作 / 學歷 / 專案 *內部* 才會出現的細項標題（如職責分區、子模組、技術點）

關鍵注意：
- 履歷中「公司名」「學校名」「專案名」彼此一律平行，**絕不**要把後出現的公司 / 學校 / 專案判為前一個的子節
- 若同一公司下有「Role 1 / Role 2」這類晉升軌跡的子標題，才用 ####
- 若無法判斷請優先給 ###（保守維持平行結構，比錯誤巢狀好）

只輸出 JSON，key 為行號（數字），value 為 # 數量（1-4）：
{"行號": 數量, ...}
